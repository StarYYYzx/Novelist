# 系统流

## 一、本体定义（系统是什么）

1. **服务对象唯一**：系统只绑定宿主。仅宿主能觉察、听见、与之对话；世界内其他
   存在无法观测到系统的任何表征。宿主可主动对他人隐瞒。
2. **信息通道**：宿主意识内。不外放声音、不投影、不留可被第三方感知的痕迹。
3. **层级**：系统高于本书世界观内的常规力量体系，其权限不受世界规则约束；
   但对**极少数特定对象**存在例外（例外项由本书在设定阶段指定，用于终局伏笔）。
4. **目的**：系统有自身目的。这个目的**不是**"帮助宿主变强"，宿主只是其手段。
   目的在全书终局揭示。

## 二、呈现规范（硬约束，人设/风格不得覆盖）

1. **【】专用**：全书范围内，中文方括号 `【】` **只能**用于包裹系统发言。
   其它任何用途（旁注、强调、术语标注、数值提示）一律不得使用 `【】`。
2. **格式**：`【<系统发言>】`。不加"系统："前缀，不套用中文引号“”，
   不写"系统说道/系统提示"这类引导语——`【】`本身就是标识。
   可独立成段，也可行内嵌入。
3. **露面频次**：每章至少 1 次系统露面（发布任务 / 结算 / 答疑三选一）；
   每章 3–5 次为宜，超过 6 次即刷屏。**连续两章无系统露面视为缺陷**。
4. **信息粒度**：以"发布任务 + 结算/余额"为主。允许宿主主动向系统提问，
   系统**有限度**回答：回答应条款化、简短；对超出当前权限的问题，
   返回"权限不足"或"数据不可显示"，不解释原因。
5. **人格统一**：中性机械——无情绪、无敬语、无寒暄，只给指令、条款、数据。
   偶发异常（权限不足 / 数据异常 / 响应延迟）作为笑点与伏笔。
   **单本之内语气必须统一**，不得在章节间漂移成毒舌、古雅或有情绪的角色。

## 三、长篇节奏模板

| 节点 | 系统该做什么 |
|---|---|
| 第 1 章 | 首次激活；**章末必须发布首个任务**，钩住读者 |
| 每章 | 至少一次系统交互（发任务 / 结算 / 答疑） |
| 每卷末 | 解锁一层权限，并给出**一句**关于系统自身来源或目的的线索（只一句，克制） |
| 全书终章 | 揭示系统目的 |

## 四、反模式（禁止）

- 系统连续两章沉默，或只在主角需要开挂时才出现（工具人化）。
- 系统对他人可见/发声，或第三方能观测到系统。
- 系统一次把自身机制解释干净（信息必须分批解锁）。
- 系统出现情绪波动、吐槽、卖萌——与人格设定冲突。
- 系统发布的任务与本章主线无关（任务必须驱动本章情节）。
- **风格层误伤**：反俗套/反 AI 味的禁用词表不得把"系统提示音 / 叮 / 机械音"
  这类题材标识直接删掉了事；正确做法是规范其呈现（用 `【】` + 低频），
  而不是让系统闭嘴。

## 五、对设定阶段的要求

勾选本卡时，设定敲定阶段需额外拍板：
- 系统名称与激活条件
- 系统货币名（如"因果值"）与获取方式
- 系统的**例外对象**（它对什么会忌惮/回避）——这是终局伏笔的种子
