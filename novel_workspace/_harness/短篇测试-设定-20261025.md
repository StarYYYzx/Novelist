# 短篇端到端测试用例：《灵田三月》— 2026-10-25

> 目的：真实 API（deepseek-v4-flash）全流程验收——种子 → 构建（含审核闸门）→
> 编译期写章（三视角判定 + 机检）→ 盘后一致性 → 终润。同时验收近期四批落地：
> FIX-1 金手指归位、craft_rules 实例化、system-flow【】机检、opening 长线目标、
> 编译闸门（DL-015/016）。
>
> 规模控制：1 卷 × 5 章（本次写前 3 章），每章目标 2400 字，修仙男频类型包。

## 一、设定正文（测试输入）

- **书名**：灵田三月
- **题材**：修仙 + 系统流（种田发育向，苟道节奏）
- **主角**：陈禾，男，青云宗外门杂役弟子，伪灵根（资质平庸）
- **金手指（cheat，应落主角卡）**：「灵田系统」——绑定后山废弃灵田的半亩田；
  面板显示作物三倍速生长，所产灵米可上交宗门兑换贡献点。
  **限制**（有限性原则）：仅对这半亩田生效；每日只能催熟一种作物；
  催熟消耗"田力"，田力耗尽须休耕三日。**产出硬通货**：宗门贡献点
  （体系内资源，非独立数值）。
- **核心冲突**：三个月后的外门大考，垫底十人逐出宗门（倒计时长线目标）。
- **反派**：外门管事王铜，克扣杂役灵米配额、把持贡献点兑换。
- **系统人格**：中性机械，偶发"田力不足/节气数据异常"提示（伏笔种子）。
- **卷纲**：第一卷"三月之期"——陈禾从被逐边缘靠灵田系统挣够贡献点,
  在大考中保住外门身份并初露头角。
- **工艺卡**：修仙男频包默认（chapter-rhythm / foreshadowing / opening）
  + 显式勾选 system-flow（验【】机检）+ shuangwen（验期待—延迟—兑现注入）。

## 五、真机发现清单（本测试的直接产出，均已当日修复或登记）

- **F0** seed 提炼污染：spec 给出叶蓝/五五开（另一本 9 月项目的设定），book 忠实消费污染 hint——**来源待查**（fake provider 解析污染或网关缓存回放）；doctor 两轮抓住，人工+脚本清洗。→ 登记排查项
- **F1** forge 子命令 --provider 默认 fake：裸跑瞬时失败且报错伪装成 JSON 解析问题。→ **已修**：fake 默认时打醒目警告
- **F2** book 节点 token 预算 2600+900/卷：固定产出早超此值，finish=length 截断成残缺 JSON。→ **已修**：基线 6000
- **F3** revise 可产出 schema 外字段（time_origin 顶层直写）落盘即崩；且 REVIEW_MODULES 的 worldview 模块 sections 含非顶层段名 time_origin。→ **已修**：段内字段 schema 白名单过滤 + time_origin 路由到 meta
- **F4** chapter 命令开头 restore 结尾从不 save：章内回写改已记账文件，**连章必被 checksum 拦**（run 命令有 save，standalone chapter 缺）。→ **已修**：章末刷新检查点
- **F5** evidence_required=True 默认下真机真实事件 0 入库（抽取不带证据格式即全拒）且 CLI 不显示拒收明细。→ **登记**：EXTRACT_PROMPT 需给证据格式示例/拒收明细进 CLI 输出
- **F6** volumes revise"精简"被理解为删卷（保护合并不防整条误删）。→ 登记观察
- **F7** doctor 自身 LLM 体检一次 JSON 截断（软失败按设计降级，留痕）→ 与 F2 同类的输出预算问题，登记
- **F8** 终润"达标无操作"无可见标记（报告 rolled_back=false 但 changed 维度缺失）→ 登记小改进
