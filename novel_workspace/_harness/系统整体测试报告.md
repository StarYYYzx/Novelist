# Novelist 系统整体测试报告

> 测试方式：以「男频修仙文」为目标，用本地 LM-Studio `qwen/qwen3.5-9b`（9B，约 20 token/s）
> 端到端生成《断玉青冥》第 1 卷 10 章，逐章拆分文件，期间记录系统缺陷。
> 工作区：`novel_workspace/proj-duanyu/`（gitignored），测试脚本：`novel_workspace/_harness/`。

## 一、成果物

| 项 | 结果 |
| --- | --- |
| 正文章节 | 10 个文件，`chapters/1-1.md … 1-10.md` |
| 总字数 | 10,347 字（单章 614–1523 字） |
| 建档人物 | 22 人（正文出场 19 人） |
| 剧情事件 | 39 条 = **真实情节事件 29 条** + 系统章级合成事件 10 条 |
| 记忆碎片 | 89 条（`memory/fragment_index.json`） |
| 人物经历史 | 16/22 人有 |
| 系统一致性告警 | **0 条** |
| 发布包 | `_harness/断玉青冥.md`（10,462 字符） |
| 端到端耗时 | 约 28 分钟（10 章 × ~160s，另 3 章因截断重生成 +~8 分钟） |

## 二、我不得不**代系统做的事**（系统缺能力的直接证据）

这部分是本报告的核心。以下 5 项本应由系统承担，实际全部由测试脚本 `novel_workspace/_harness/` 代做：

1. **代写设定圣经与细纲** —— 无「世界观构建师」「大纲师」子代理。
2. **把圣经注入生成上下文** —— `produce_chapter` 默认 `system_prompt` 只有一句
   "你是主编剧，负责指挥创作。"，世界观/文风/人物卡**从不进入 LLM 上下文**。
3. **代行「记忆编纂员」抽取真实事件** —— 系统只会回写章级合成事件。
4. **代做正文级一致性扫描** —— 规则引擎只查 bible 内部引用，完全不扫正文。
5. **手工回滚记忆** —— 章节重写后旧事件无法撤回，只能直接改文件。

## 三、缺陷清单

### P0 · 严重（阻断，建议优先修）

**B-01 无子代理机制，当前不是多 Agent 系统**
`core/subagent.py` 在 docs/08 §2 的目录结构里列出了，但**代码中不存在**。
docs/05 §3 定义的 7 个命名子代理——世界观构建师、大纲师、文字匠、审校师、伏笔监理、
检查员、记忆编纂员——**无一实现**。当前链路是：`主编剧 → 一次 LLM 调用 → 文本直出落盘`。

**B-02 圣经不进生成上下文，等于没有"唯一事实源"**
ADR-004 把工作区定义为单一事实源，但生成时只把「细纲 + 检索到的记忆」送给模型；
世界观、文风、人物卡全部缺席。

对照实验（`_harness/repro_b02.py`，可直接复现）：原样跑一次 `novelist chapter
--provider lmstudio`，细纲里**不写**苏晚的性别，结果——

| 检查项 | 结果 |
| --- | --- |
| 性别漂移 | **1 处**：正文出现"苏晚心上。**她**…" |
| 章节完整性 | **截断**：584 字，末字"无" |
| 细纲核心事件（拾得断玉佩） | **未写进正文**（400 token 预算不够，见 B-05） |
| 系统一致性引擎告警 | **0 条**（对上述三类问题全部无感） |

另外，本轮正式生成前的首次 CLI 直出还出现过「卷名漂移」（把大纲定的"青云试炼"
写成"断玉录"）与「凭空造人」（正文出现圣经中没有的"李长风"）。这两项在对照实验中
未复现（本次模型没造人），属偶发，但同因——圣经信息不在上下文里。

修法建议：`produce_chapter` 增加 `context_injector`，按章节装配 世界观 + 文风 + 本章出场人物卡。
本次测试由 `_harness/run_novel.py::build_system_prompt()` 代做，注入后：性别零漂移、
零造人、章节标题全部遵循大纲。

**B-03 无事件抽取，ADR-013 未落地**
`produce_chapter` 只回写一条 `kind="chapter"` 的合成事件「完成第 X 卷第 Y 章」，
不含任何情节内容。docs/05 §5.4 的"每落定一个事件即实时回写"、A9 验收项均**无法真正满足**。
本报告里的 29 条真实事件全部由 `_harness/run_novel.py` 代行编纂员产出。

### P1 · 重要

**B-04 生成无完整性校验**
`produce_chapter` 只判断 `len(final) >= direct_words_floor`（默认 20 字符），
被拦腰截断的章节同样记为成功。10 章中 **3 章（2/9/10）截断在句子中间**，靠人工发现后重生成。

**B-05 CLI 无法指定生成预算**
`cli.py:193` 对 lmstudio 硬编码 `gen_tokens = 400`，且无 `--gen-tokens` 参数。
400 token 写不完一章（首章因此丢失了细纲里的核心事件"拾得断玉佩"）。

**B-06 CLI 无 promote/publish 命令**
CLI 只有 8 个命令：`chapter export grant init run server stats status`。
`promote_draft` 工具存在（sensitive），但**没有 CLI 入口**，草稿永远转不了正式章节；
`export` 默认只读 `chapters/`，不带 `--include-drafts` 就导不出任何内容。

**B-07 记忆层无修订与回退**
`MemoryWriter` 只有 `append_*`。docs/06 §4.4 声称冲突记忆"可回滚"，但未实现。
重生成第 2/9/10 章时，旧事件会与新事件并存（重复且矛盾），只能直接改 JSON 文件清理。

**B-08 一致性引擎覆盖面过窄**
只有 R-REF（校验 `characters.*.relationships[].target`）与 R-TL（校验 timeline.json 顺序）两条，
**都不读正文**。以下全部无检查（实测均在本次产出中出现或存在风险）：

| 检查项 | 实测情况 |
| --- | --- |
| 现代词汇 | `1-10` 出现「厚眼镜」（修仙文） |
| 西方典故 | `1-10` 出现「达摩克利斯之剑」 |
| 战力体系表述 | 同一本书里混用「炼气三层」与「炼气一重」 |
| 称谓与身份 | `1-10` 中筑基修士称炼气三层的苏晚为「前辈」 |
| 世界观铁律 | 「修士不可对凡人出手」是否被违反，无从校验 |
| 大纲覆盖度 | 22 建档人物中 3 人（血河老祖、柳氏、阿萝）正文零出场 |
| 跨章连续性 | 伏笔/伤势/物品去向无校验 |

**B-09 敏感词表默认为空**
`ModerationPrechecker(banned=None)` → 空表，`scan()` 恒返回空列表。
ADR-015 的"上游预检降低审核命中"形同虚设。

### P2 · 一般

**B-10 人物卡 schema 无 `gender` 字段**（**本次已修**）
`schemas/bible/characters.schema.json` 原无性别字段，且 `additionalProperties: false`
把扩展也挡住了。已补 `gender`（enum: male/female/unknown）与可选 `age`。
缺失时 LLM 必然漂移人物性别——这是 B-02 造成实际损害的主因之一。

**B-11 冲突双检在真实运行中从未触发**
29 条真实事件、0 冲突。规则层（重复入库、bible 引用完整性）与语义层（未注入）
在本次真实语料上一次都没生效，**无法证明其有效性**，需要专门构造用例验证。

**B-12 大纲覆盖度无保障**
docs/05 §3 的「检查员」子代理（细纲→正文覆盖检查）未实现。10 章细纲共 29 个 key_events，
是否都写进正文没有任何机制核验；3 个建档人物全程零出场也无告警。

**B-13 导出包书名取的是 project_id 而非 title**
`core/export.py::export_project` 首行写 `f"# {project_id}"`，发布包标题成了
`proj-duanyu`，而 `project.json.title` 里明明写着「断玉青冥」。

**B-14 元叙事泄漏无系统级防护**
首次直出时正文出现"那是他在**第一章**捡到的"。本次靠在 prompt 里加硬性禁止才消除，
属于提示词层面的人肉约束，不是系统机制。

## 四、表现正常的部分

- **记忆检索与增量索引**：回写即入索引（89 碎片），`rag/vectors.json` 语义模式可删可再生已验证。
- **权限门禁**：`promote_draft`（sensitive）默认 `ask` → 无审批通道时抛 `DeniedError`；
  策略文件把 sensitive 设为 allow 后成功转正。danger 默认 deny 符合 F6.1。
- **一致性规则引擎**：bible 自洽时 0 告警；构造的悬空引用与倒退时间线能被正确抓出（既有测试覆盖）。
- **串行链路**：10 章严格串行，无并发写冲突，事件回写未阻塞。
- **禁用词**：`style.json` 里配的「系统/签到/叮」零命中（模型遵守了）。

## 五、建议的修复顺序

1. **B-02 圣经注入**（成本最低、收益最大——直接决定成稿能不能看）
2. **B-03 + B-01 编纂员与子代理框架**（A7/A9 验收的前提）
3. **B-04 + B-05 生成完整性校验与预算可配**（否则产出物带截断）
4. **B-06 promote CLI**（否则正文永远停在草稿态）
5. **B-08 审校师（LLM 语义检）**（唯一能覆盖文风/世界观/逻辑的路径）
6. **B-09 敏感词表** + **B-07 记忆回退**

## 六、复现方式

```bash
# 1) 搭建工作区（圣经 + 细纲，系统无世界观构建师/大纲师，由脚本代写）
python novel_workspace/_harness/setup.py

# 2) 串行写章 + 编纂（每章约 160s，10 章约 25 分钟）
python novel_workspace/_harness/run_novel.py --chapters 10 --tokens 800

# 3) 检查截断
python novel_workspace/_harness/check_truncation.py

# 4) 重生成问题章节
python novel_workspace/_harness/regen.py 2 9 10

# 5) 转正 + 一致性 + 扫描 + 导出
python novel_workspace/_harness/finalize.py
python novel_workspace/_harness/scan_names.py
python novel_workspace/_harness/scan_style.py
```
