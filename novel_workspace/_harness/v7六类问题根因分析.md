## 二、逐类根因

### 问题 1：文本拼接与重复（最严重）

**症状定位**：
- ch4：同一场景（狼妖白拦路 → 绑云飞扬 → 雪见逼退）渲染两遍——L3-45（简版）与 L47-134（详版，含两遍【绑定成功】L27/L49、【解绑成功】L102/L122、云飞扬拍肩 L98/L118、雪见质问 L41-45 重复）。
- ch3：开头 L3-95（白天藏经阁寻残页）→ 中段 L97-179（夜巡遇鬼面）→ 结尾 L181-199 **又回藏经阁三层把残页发现重演一遍**（L69 vs L189「五五开……血月魔尊……」，两处一字之差）。
- ch5：事件③（灵脉石）开头 L141 泄漏细纲标题「## 第5章 秘境第一滴血」，并把朱烈对峙/雪见绑定重演（L143-151 朱烈余波、L151 又勾云飞扬衣袖、L187 再绑雪见、L213 雪见质问与 L129 逐字重复）。
- ch1 已存在同构模板（周泰/王福 → 陈松，两段都是"绑强者 → 威压 → 对方逃窜"）；ch2 45-51=111-113 逐字重复（v7 报告已记）。

**机制链**：
1. 上游：细纲把"同一场景的两个阶段"写成两个 key_event（ch4「遭遇狼妖白拦路」/「绑云飞扬护队，雪见出手」本质是同一场的起因与解决）；细纲要点把「结尾钩子：残页写血月魔尊」单列为一条，而该钩子与事件①内容（发现残页）就是同一件事。
2. 生成编排（orchestrator.py:1235 起）：按 key_events **机械迭代**，每事件独立 prompt。事件间上下文只有【上文接缝】= 上一事件尾部 300-400 字（orchestrator.py:528-530、L1219 `seam=max(200,min(400,_SEAM_CHARS))`）+ 记忆检索片段。**没有"上一事件确立了哪些事实"的结构化回注**。
3. 拼接去重（orchestrator.py:1424-1426 `strip_seam_overlap`）只剥**首尾字面重叠**；ch4 双版本是"同场景不同措辞重演"，字面不重叠 → 剥不掉。
4. 完整性检测（polish.completeness 的 dup_paragraphs/dup_sentences）只抓**近逐字重复段**；ch3/ch4/ch5 的重演是"同事件两版措辞"，相似度不足 → 0 告警（run_v7_log：ch3 dup=0/0、ch4 dup=0/0、ch5 dup=1/0）。
5. 事件级审校（reviewer.py:30-31 CATEGORIES）类别表：设定矛盾/人设漂移/称谓失当/时间线/战力越级/事实前后矛盾/细纲未覆盖/伏笔/其他——**没有"与本章前文场景重复/雷同"类别** → 语义审校也不拦（ch3/4/5 review_blocks 全 0）。
6. 记忆层（chronicler）：ch4 双版本被抽成**两条同义事件**（plot_events：「触碰到…云飞扬的衣袖」+「接触云飞扬并同步其修为」）→ 记忆层把重复叙事当新事实固化，后续事件检索又引回重复。

**根因定性**：**细纲 key_events 切分粒度/语义边界 + 生成器无"事件间事实状态"与"场景重演检测"**。65bb8de 只修了审校 scope（整章误报），没动"重复"检测，问题 1 在新代码上**依旧存在**。

**修复方向**：
- 细纲层：forge 生成 key_events 时校验"相邻事件场景/结局状态不重叠"（或允许合并语义重叠事件）。
- 生成层：事件间维护「已确立事实清单」（场景/在场者/绑定状态/结局）结构化回注进下事件 prompt；或将【上文接缝】扩为"前情摘要+接缝原文"双段。
- 门禁层：completeness 增"跨事件同场景检测"（事件间人物/地点/动作序列相似度）；审校 CATEGORIES 增「与本章前文重复」。
- 记忆层：chronicler 抽取对同章近似事件去重（语义相似度阈值），别把两版都入库。

### 问题 2：时间线与场景跳跃无过渡

**症状定位**：ch3 白天藏经阁 → 直接「夜色如墨」夜巡外山 → 打完鬼面 →「远在藏经阁三层」白天残页重演（L181），一天内场景三次跳变无任何过渡；ch4 云清瑶 L174「不知何时出现在身侧」——她不在细纲 ch4 cast、无来由入场；ch5 L141 起场景在密林内原地重开。

**机制链**：
1. 事件 prompt 的【本步骤】只给事件一句话（orchestrator.py:511），无"上一事件结束时：谁在哪、什么时间、接下来去哪"的接续状态；场景切换全凭模型从 300 字接缝里自行推断，接缝一短就跳。
2. ADR-021 世界广播选角（谁该在场）**尚未落地**——ch4 细纲没点名云清瑶，cast_from_text（orchestrator.py:1296）只按事件文本字面抓名字，抓不到她 → 她无卡无动机"突然现身"（cast_injection 也没给她卡，L174-176 她行为全靠模型即兴）。
3. worldstate 只记人物 location 字符串（藏经阁三层/外山乱石坡/秘境入口），事件间不校验"上一事件地点 → 本事件地点"的物理可达/衔接；chronicler 把 ch3 外山打斗记成「鬼面散人重伤跌出秘境」（plot_events），地点张冠李戴还进了记忆。
4. v7 旧代码的事件级审校 scope bug：审校以为在审整章，看到片段内场景单一不报时间线；65bb8de 修 scope 后**跨事件**时间线仍不在任何单次审校的视野内（每个事件只审自己）。

**根因定性**：**事件循环缺"场景接续状态机"**（时间/地点/在场者每次事件生成前必须确定并从上一事件继承），叠加 ADR-021 选角未落地。

**修复方向**：
- 事件间维护 story-clock：`上一事件结束时 {时间, 地点, 在场者, 悬念}`，生成事件 N 前强制注入并写"场景过渡句"要求（从 X 到 Y 须有一句转场）。
- ADR-021 世界广播选角落地：ch4 这类"云清瑶该来护叶岚"由选角调用决定并注入其卡与动机。
- chronicler：校验抽取事件的 location 与前后事件可达性（规则化），不一致降级或告警。

### 问题 3：系统规则混乱

**症状定位**：
- 触发条件矛盾：ch1 L15「接触即绑定」、L75「绑定协议强制激活」；ch2 尾系统**主动弹窗**「检测到宿主被调查，是否绑定调查者？」叶岚可拒绝（不接触、有选择权）——两套机制并存。
- 对象知情矛盾：ch1 云清瑶绑定瞬间有感知（L45 同源共振、修为牵引）；ch4/ch5 云飞扬、雪见被绑**完全无感**（ch4 L90「傻小子，倒是个合格的工具人」）。
- 越阶矛盾：ch4 绑炼气八层云飞扬去"护送队伍"对峙金丹初期狼妖白（L33 挑衅）；ch5 绑金丹后期雪见"反杀"元婴中期朱烈——圣经无越阶上限，全靠模型即兴。
- 新功能凭空出现：ch5 L199「绑定强化符」弹窗——bible items.json **无此道具**，worldview.rules 无此机制，系模型从细纲「灵脉石可强化绑定」一句话实体化而来；chronicler 还把它写进 worldstate items（叶岚获得"绑定强化符"）——**未登记道具被记忆层追认**。
- 系统界面人格漂移：ch1 L67-71 系统毒舌人格化（"呵，大学生？就这？"）与 L15 冷机械音并存；ch4 L47 又变「冰水渗进毛孔」式描述。

**机制链**：
1. settings.json `set:wuwu` 只写「接触即可绑定对象，绑定期间修为与对象一致；同时只能绑定一人；解绑后修为回落」——**没写**：能否主动提议/宿主可否拒绝/对象是否知情/能否越阶/上限多少/系统人格与界面协议。bible 欠定义 → 每个事件独立生成时模型各自脑补，且 ch1/ch2 的两套演绎**都进了记忆**（chronicler 不判机制一致性），后续章检索到哪套就采信哪套。
2. worldview.rules 只有两条（同门不得相残 / 绑定期间修为一致）——**无系统行为规范、无越阶条款**。
3. 新道具/新机制无注册闸门：生成器造出"强化符"，R-ITEM（rules.py:194 起）只查"人物持有 bible 未登记物品"——若 R-ITEM 已跑应该拦……但事件循环内审校只跑语义（reviewer），R-ITEM 是 run_consistency 的盘后规则（orchestrator 事件内不调 rules.py），且 run_v7 脚本没在每章后跑 run_consistency 全量盘检 → 无人在线拦，worldstate 照单全收。
4. realm_fluctuates（worldview.json：["char:yelan","叶岚"]）把叶岚修为波动整体豁免 R-STATE——设计本意是"绑定同步的合理波动不告警"，实际连"炼气八层对峙金丹妖兽、金丹后期反杀元婴"这类**叙事性越阶**也一并豁免（R-STATE 只看 worldstate realm 变化，不看正文打斗叙事）。

**根因定性**：**bible 机制规格欠定义（触发/控制权/知情/越阶/界面协议全缺）** + **生成/回写链路无"系统规则一致性 + 新道具注册"在线门禁**。

**修复方向**：
- bible 扩 `set:wuwu` + worldview.rules：明确「绑定须接触；绑定对象无感；宿主不可拒绝已触发的绑定；解绑回落；宿主真实境界不变；不得以绑定修为越阶碾压高于对象一境以上之敌（或：只能发挥到对象境界）」+ 系统界面统一为面板播报协议。
- settings.json 增「系统机制条目」作为独立知识类目，事件生成时若本事件含绑定动作则强制注入。
- 新道具/机制注册闸门：事件级审校类别增「新增未登记道具/功法/组织」；chronicler 对 worldstate delta 里出现 bible 无登记的新实体名告警而非静默入库。
- R-STATE 豁免收窄：realm_fluctuates 只豁免"数值回落合法"，正文叙事越阶交给审校「战力越级」类 + 新增境界压制规则行。

### 问题 4：伏笔与主线失控

**症状定位**：ch3「血月魔尊」残页、ch4「秘境深处有与本系统同源的气息」（L114）+ 鬼面「三十年前的那个孩子，又出现了」（L168）、ch5「同源，却更深更诡」（L73）——关键词密集抛出但彼此无逻辑链；「三十年前的孩子」与叶岚（20 岁大学生魂穿、char:yelan 无身世伏笔）对不上，纯为悬念而悬念；threads 里也无此线索登记。

**机制链**：
1. 细纲把悬念写成**章末钩子指令**：ch3 要点「结尾钩子：残页上写着五五开……血月魔尊……」、ch4 要点「结尾钩子：系统提示秘境深处有与本系统同源的气息」——forge 层在细纲里主动布置了"每章一钩"，生成器机械执行 → 钩子密度高但无铺垫链。
2. plot_threads.json 的 thread desc 只有一句话（「五五开系统的来历——与上古魔尊血月残魂的渊源」），**无 planted 章/披露节奏/关联线索**；R-THREAD（rules.py:345 起）只校验"bible 内 thread 是否兑现"，**不拦正文新造悬念**。
3. settings.json `set:mozun`（血月魔尊）标了 `first_ch:17` 却 `revealed:true`——首次交代状态机本该 ch17 才披露，但 ch3 残页就让"血月魔尊"四字登场且无任何门禁拦截（revealed=true 时 even 不延迟）；forge 细纲也不读 settings 的 first_ch，造成"ch3 细纲就写血月魔尊钩子"与"bible 说 ch17 披露"直接冲突。
4. 模型即兴悬念（三十年前的孩子/同源更深诡）无惩罚——生成 prompt 只有正向"结尾钩子"指令，没有"禁止抛出未登记线索"纪律行。

**根因定性**：**细纲层"每章必抛钩"的默认 + bible 伏笔管理只有一句话 desc 无节奏/无登记闸门 + 披露时间（first_ch）与细纲脱钩且未执行**。

**修复方向**：
- plot_threads schema 增：planted_at / 披露计划（第几章首次提及、第几章加深、第几章兑付）/ 关联 thread / 禁止提前全名披露的实体（如"魔尊"ch17 前只能以"残页被抹去字迹"暗示）。
- forge 细纲生成时注入「本章可提及线索白名单 + 禁止新造悬念」约束，钩子必须挂已登记 thread。
- settings first_ch 纳入披露状态机执行（revealed 由状态机翻转，不预先 true）；R-THREAD 增加"正文出现未登记悬念词/人名"检测（可复用 R-LEX 词表机制做"悬念词登记表"）。

### 问题 5：人物动机与人设（配角触发器化）

**症状定位**：
- 雪见 ch5 先冷眼旁观（L43「没理会叶岚死活」、L93-97「不帮忙也不补刀，看戏」）又替青云宗执法（L173「青云宗铁律，同门不得相残。谁敢动手，休怪我雪见剑下无情」——她一个万剑宗弟子替青云宗立规矩？）又主动点破叶岚（L127/L213「你的修为，刚才变了两次」）——立场前后跳。
- 云清瑶 ch4 无来由现身护叶岚；ch1 她绑定后"同源共振、修为被牵引"却毫不起疑深究（L45-53 只眉头微蹙）。
- 秦叔 ch3 对叶岚"废物"鄙夷（L141）与细纲设定（古板尽责、绑定对象）之间只有模板化反差，无个人动机线。
- 鬼面散人：ch3 夜袭青云外山（细纲 so），char:gui arc 却写"秘境中的疯魔散修"，bible 与细纲角色定位冲突 → ch4 他又出现在秘境口（L162），苏婉台词引用了一个正文没发生过的"上次跌出秘境"（L164）——角色行为跟着场景飘。

**机制链**：
1. bible 人物卡信息密度低：core_traits 2 个词（雪见"冷/纯粹"、云清瑶"飒爽/护短/直觉准"）+ arc 一句话，**无"本场会怎么行动/不会做什么/对主角态度演变"的行为规格**；人物卡注入（ADR-020 cast_injection）给的是 trait 不是动机 → 模型只能套模板（冷=旁观、护短=现身）。
2. ADR-020 N3 人物调度单（build_direction）本应产出"本场体现/禁忌"（方向单 v1-cN-eN.json），但 v7 首跑 directions_built=0（旧代码）→ 本批 ch1-5 全无调度约束；新代码 14/15 覆盖率也说明还有事件拿不到调度单（build_direction 失败静默降级）。
3. 人物首现章管理失效：char:yunfei 云飞扬 first_appear ch5，但 **ch4 细纲 key_event 就点名他当绑定对象**（细纲先于 bible 卡更新），生成层 JIT（_jit_characters）按细纲补卡 → 卡与章序错位；云清瑶同理，ch4 细纲没点名却因 ch1-2 活跃被模型从记忆里捞出来"突然现身"。
4. R-CAST（rules.py:285 起，出场覆盖度）只盘"建档人物是否零出场"，不查"正文出现未建档/行为矛盾"。

**根因定性**：**人物卡只有 trait 无行为规格 + 调度单（N3）覆盖率不足/失败静默 + bible first_appear 与细纲出场脱钩无校验 + ADR-021 选角缺失导致无卡人物入场**。

**修复方向**：
- 人物卡 schema 增 `scene_behavior`：2-3 条"本角色遇到 X 场景的可观察行动 + 绝不做的 Y"（forge 生成，低密度）。
- N3 调度单失败不再静默：build_direction 降级时区分"无人物/LLM 失败"并在章末汇总告警（已建议）。
- forge 细纲生成后校验：出场人物 ⊆ bible first_appear ≤ 本章的人物 ∪ 已登场人物，冲突回炉。
- ADR-021 选角落地后：所有正文出现人物必须过"选角名单 ∪ cast_from_text 命中"门禁，名单外人物入场告警。

### 问题 6：战力体系崩塌

**症状定位**：
- ch4 L21 陈松"金丹后期" vs L142 同章"筑基后期"（bible=筑基后期）——同章自相矛盾。
- ch4 L33：叶岚绑炼气八层云飞扬后当众"挑衅"金丹初期狼妖白（炼气 vs 金丹差两境）。
- ch5：绑金丹后期雪见 → L107-111 一击把元婴中期朱烈打到胸骨凹陷狂喷血——**金丹后期秒杀元婴中期**（差一境且是中期对后期反杀）。
- worldstate 叶岚 realm 被记成 ch1 筑基中期 / ch3 金丹中期 / ch4 炼气八层 / ch5 金丹后期——**绑定临时修为被当真实境界永久落盘**，后续"叶岚当前境界"参照全错。
- ch3 L125 秦叔内心"深知化神初期的恐怖"——秦叔金丹中期 vs 鬼面化神初期（char:gui 化神初期），细纲却让他带队周旋打退化神（差两境）。

**机制链**：
1. bible 无境界压制规则：worldview.rules / set:jingjie 只罗列五境名称，**无"高境对低境碾压/跨境战斗合理性边界"条款**；审校「战力越级」类别无规则可依，只能靠模型自觉。
2. 细纲自造越级戏：ch5 key_event「叶岚绑定雪见以金丹修为反杀」+ ch4「绑定云飞扬护送队伍（对金丹妖）」——forge 细纲设计时就无视境界差；且与 bible char:zhu arc「被叶岚绑定化神老祖后击退」（需绑化神墨无极，char:mo first ch6）矛盾——细纲把本该 ch6 后才有的解法提前到 ch5 用金丹硬顶。
3. 记忆层污染（最隐蔽）：chronicler 把"绑定瞬间的 realm delta"直接写入 worldstate.history（叶岚 ch1 筑基中期、ch3 金丹中期、ch5 金丹后期），而 R-STATE 的 realm_fluctuates 又把这套波动**整体豁免** → 一致性引擎对叶岚的境界彻底失明；后续章检索"叶岚修为"拿到的是金丹后期（worldstate 现值），越写越离谱。
4. 生成 prompt 无"当前真实修为 + 绑定对象修为 + 对手修为"三值对照纪律行：事件若含战斗，应把三者显式列出让模型按境界差写结果。

**根因定性**：**bible 无境界压制规则 + 细纲越级设计（与 arc 冲突）+ 记忆层把绑定临时修为当真实境界（realm_fluctuates 豁免过度）**。

**修复方向**：
- bible 增境界压制条款（如"差一境可周旋难取胜、差两境必败/需智取或外力"，写入 worldview.rules 供注入与审校共用）。
- forge 细纲对含战斗的 key_event 做境界校验（出场者境界差 > 阈值 → 标注"如何赢"的机制，不许裸越级）。
- worldstate 落盘区分 real_realm 与 sync_realm（绑定临时修为另存），R-STATE 只对 real_realm 做连贯性检查；realm_fluctuates 豁免收窄为"只豁免数值波动、不豁免叙事越阶"。
- 战斗事件 prompt 注入三值对照（叶岚真实境界/绑定对象/对手）并给越级收束要求。

## 三、横切根因总结（三层）

1. **上游 bible/细纲（源头质量）**：机制规则欠定义（系统协议、境界压制、伏笔节奏、人物行为规格全缺）；
   bible first_appear / settings.first_ch / char.arc 与细纲内容互相矛盾且无生成前校验；
   forge 默认"每章一钩"诱导悬念滥用。
   → 六类问题里 3/4/6 的主根因在此，5 的一半在此。**投入产出比最高**。
2. **生成编排**：事件循环机械迭代，事件间只有 300-400 字接缝、无"已确立事实/场景状态"结构化回注；
   场景切换无过渡要求；调度单覆盖率不足且失败静默；ADR-021 选角（谁该在场）未落地。
   → 问题 1/2 的主根因在此。
3. **记忆回写与门禁**：chronicler 对"双版本事件/未登记道具/绑定临时修为/张冠李戴地点"照单全收进
   worldstate/plot_events（污染源）；事件循环内无 rules.py 确定性门禁（R-ITEM/R-STATE/R-THREAD
   都是盘后 run_consistency 才跑，而 run_v7 脚本没接盘后全量盘检）；审校类别表无"重复/新造悬念/
   未登记道具"类。R-STATE 的 realm_fluctuates 豁免过度让战力失明。
   → 问题 1/3/6 的"为什么没人拦住"都在这层。
