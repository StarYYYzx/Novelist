# Prompt 全链路作用审计——「当前系统的 prompt 是否发挥了完整作用？」

> 审计对象：src/novelist 生成侧全部 prompt 装配路径 + proj-yelan3 真实数据投喂面。
> 审计基准：v7（Qwen3.6 五章）实测形态——run_novel_v7.py 全特性开关
> （event_loop / polish / event_review / event_polish / readback / knowledge_llm /
> supplement_settings=True，ADR-020 四件套默认全开）。
> 日期：2026-09-02。

---

## 总判定

**Prompt 机制约八成在位、且 v7 实测时全部真实接入了链路**——问题不是"没接上"，而是三类：

1. **无米下锅**：注入机制齐全，但 bible 数据字段稀疏，prompt 渲染出来是空壳（人物卡 9 字段
   过半空段、世界铁律仅 2 条、系统协议文本不含关键条款）；
2. **无条件纪律被改成概率命中**：system prompt 里三处"不在此注入、由知识层检索"的注释
   把**每章必达的纪律**降级为 RAG 命中才有（势力/伏笔/历史教训），而 RAG 命中本身是
   「模型生成查询 × topk 截断 × 关键词重合」三重概率；
3. **指令无确定性兜底**：输出纪律、抽取纪律全部靠模型自觉，事件循环内不跑任何
   rules.py 确定性检查，审校类别表又没有"重复/新造"类 → 违反即静默通过。

外加一个**真死参数**（`lessons`）和一条**反向追认通道**（supplement_settings 把模型的
自由发挥洗白成设定再入库）——后者是"强化符凭空出现"的完整闭环，此前未点透。

## 二、断点与打折（证据 + 行号）

### 2.1 死参数：`lessons` 收而不用（真 bug）

- `build_system_prompt(bible, cast, vol, ch, genre=..., lessons=...)` 签名收 `lessons`
  （`context.py` L145），**函数体全程零引用**（L151-244 无一处使用）。
- 调用链真实传值：`orchestrator.py` L1098-1101 `_lesson_lines()` → `build_chapter_context(lessons=...)`
  → `build_system_prompt(lessons=...)` → 丢弃。
- 设计史：第 7 轮"历史教训随圣经注入"（docstring L148 仍是这个说法）→ 第 8 轮 RAG 化后
  改由知识层检索，system prompt 级注入被删，**参数没删干净**。
- 后果：`review_lessons.json` 现有 3 条纪律（陈松修为统一筑基后期等）只剩 `knowledge.py` L122-129
  一条**概率命中**路径（lesson 条目 keywords=[category]，查询词是模型按剧情生成的——
  剧情词撞上"设定矛盾"这类类别词的几率极低）。
- 定性：**中性偏负**。这 3 条教训若真的无条件注入正文 prompt，反而会诱发上一轮修的
  "细纲未覆盖误报→诱导提前补写后续事件"。正确的归宿是把"陈松修为统一筑基后期"这类
  **确定性规则**写进 rules.py（R-STATE 引用一致性），而不是靠 LLM prompt 或 RAG 碰运气。

### 2.2 无米下锅：人物卡数据饥饿（定量证据）

proj-yelan3 `bible/characters.json` 26 卡字段覆盖：

| 字段 | 有值卡数 | 字段 | 有值卡数 |
|---|---|---|---|
| gender | 26/26 | relationships | **3/26** |
| power | 26/26 | possessions | **1/26** |
| core_traits | 26/26 | age / notes / behavior / goals | **0/26** |
| arc | 26/26 | | |
| aliases | 26/26 | core_traits 词数 | **23/26 卡仅 2 词** |
| first_appear | 26/26 | arc 长度 | 25/26 ≤ 40 字 |

对照注入机制的设计需求：

- `render_card_line` 渲染 9 字段（`director.py` L183-222），但 relationships（3/26）、
  possessions（1/26）→ **过半渲染为空段**；"关系：对谁什么态度"（决定对白腔调）26 张卡只有 3 张有。
- `DIRECTOR_PROMPT`（`director.py` L35-55）要求"性格要点 ≤3 条、必须来自人物卡、不要发明新特质、
  各人指令彼此不同"——**卡里只有 2 个 trait 词**，导演无米下锅：要么造词（违反纪律）、要么同质化。
  ch3/ch4 调度单缺人、降级的深层原因之一。
- 云清瑶/雪见/鬼面散人"行为前后矛盾、沦为弹窗触发器"（六类问题之五）：人物卡没有
  行为规格字段（scene_behavior/goals 0/26），prompt 能约束的只有 2 个 trait 词 + 一句话弧线。

### 2.3 设定文本不含协议条款（prompt 的能力边界 = 数据的边界）

- `worldview.rules` 仅 **2 条**铁律；`power_system.note` 仅一句话（五境口诀）。
- `settings.json` 8 条，其中核心机制 `set:wuwu` 全文：
  > 五五开系统：接触即可绑定对象，绑定期间修为与对象一致；同时只能绑定一人；解绑后修为回落，
  > 自身修炼境界独立累积。
- **没有**：能否主动提议 / 宿主可否拒绝 / 对象是否知情 / 越阶上限（绑到高自己太多境界会怎样）/
  界面协议（弹窗？强制？）。正文 ch1 强制激活 vs ch2 弹窗可拒、绑定感知时有时无——不是
  prompt 没写清，是**可注入的设定原文就没有这些条款**，模型只能在文本缺口里自由发挥。
- "严禁越阶被反复打破"同理：铁律表、境界条款都不含压制关系 → prompt 无处可引用。

### 2.4 事实连续性只有软指令、没有硬状态回注（结构性缺口）

- system prompt 纪律"事实一致：前情里已发生的事不得重复发生或自相矛盾"（`context.py` L39-40）、
  事件 goal"不要重复上文已经写过的内容"（`orchestrator.py` L513）——**全是让模型自觉的软指令**。
- 事件循环里模型能看到的唯一硬锚是 **300 字接缝尾巴**（`orchestrator.py` L1219 seam=200-400，
  接缝原文 L528-530）+ 记忆检索行。**没有"本章已确立事实清单"这样的结构化回注**。
- 后果：ch4 同场景两遍各自绑定（L27/L49）、ch3 首尾循环重演残页发现——同一事件被写第二遍时，
  模型并不持有"这段已写过"的确定性事实，`strip_seam_overlap` 只剥字面重叠抓不到语义重演。

### 2.5 势力/伏笔/教训全 RAG 概率化（无条件 → 命中才有的静默降级）

- `context.py` L190 注释"势力不在此全量注入……由知识层检索"；L234-235 注释"伏笔与历史教训
  不在此注入……事件级注入"。system prompt 因此**永远不含**势力/伏笔/教训。
- 事件级 RAG 路径是三重概率叠加：`plan_queries`（`knowledge.py` L231-249，模型生成查询，
  失败退化为事件文本）→ `retrieve` 融合检索（L216-229）→ `KIND_TOPK` 截断
  （L36-39：thread 2 条 / lesson 2 条 / faction 2 条）。
- 后果：伏笔"血月魔尊/三十年前的孩子"被随意抛出毫无铺垫——forge 细纲每章必抛钩，而
  **把"该抛哪条、何时收"写进正文的通道只有 RAG 命中**；RAG 不命中 = 模型对伏笔表一无所知。

### 2.6 反向追认通道：supplement_settings 把自由发挥洗白成设定

- v7 实测 `supplement_settings=True`（run_novel_v7.py L95）。机制：每事件结束后
  `_supplement_settings`（`orchestrator.py` L1336-1341）让 LLM 看事件文本，**出现新专有名词
  就补一条 settings 条目**，后续事件可命中注入。
- 这条通道**没有"对照注册表校验该词是否应存在"的上游检查**——模型正文里自造的"强化符"
  一经出现，立刻被补档成设定条目（上一轮已证 memory/plot_events 里被追认），
  后续章引用它反而"有据可依"。
- 定性：这不是"prompt 没作用"，是**一条 prompt 驱动的主动追认路径放大了模型失控**。
  设计意图是滚动补充世界观（合理的），但缺少"新词须在 bible 已登记名册内或经人类确认"的闸门。

### 2.7 编纂纪律完备、双检却查不到"忠于正文"

- `EXTRACT_PROMPT` 已沉淀大量实测教训（`chronicler.py` L45-50："借用/同步他人境界不是修为变化
  "、"修为波动只记主角本人"、"能力/权限/警告是抽象概念不是物品"）。
- 但 commit 的冲突双检（L309+，`MemoryWriter`）查的是**记忆与记忆之间**的冲突
  （重复入库/引用完整性/语义回调），**不查"抽取结果是否忠于正文"**。
- v7 实测：ch3 外山打斗被抽成"鬼面跌出**秘境**"（地点张冠李戴）、绑定临时修为当真实 realm、
  强化符被追认——抽取错误与既有记忆不冲突 → 双检放行。纪律写进 prompt ≠ 模型遵守，
  抽取侧没有确定性 gate（如地点必须在 locations 名册内、境界变更须与 R-STATE 对齐）。

### 2.8 审校类别表缺两类 + 盘后只送尾部 3000 字

- CATEGORIES 九类（`reviewer.py` L29-32）：设定矛盾/人设漂移/称谓失当/时间线/战力越级/
  事实前后矛盾/细纲未覆盖/伏笔/其他——**没有"与前文重复/同场景重演"、"未登记道具/新造悬念"**。
  上一轮根因分析里 ch3/4/5 的 review_blocks 全 0 不是审校瞎，是**表外问题报不出来**。
- 盘后整章审校只送 `text[-3000:]`（`reviewer.py` L119）——章长超 3000 字时前半章不在视野
  （事件级审校不受影响：每事件 piece 短，全量在 scope 内）。
- 细纲对照也只给 `gist_text[:800]`（L115），生成侧却给了 1200（`context.py` L256）——审校
  参照物比生成参照物更短，前后 400 字的要点审校师看不到。

## 三、执行层判定：哪些靠模型自觉（无兜底清单）

| 纪律 | prompt 出处 | 确定性兜底 | 现状 |
|---|---|---|---|
| 禁用现代词/现代喻体 | `context.py` L207-209；R-LEX | 仅盘后 `run_consistency` | 事件循环内不跑 → 违规即静默通过（v7 ch4"黑板"） |
| 事实一致/不重复 | DISCIPLINE L39-40 | 审校语义层 | 类别表无"重复"类 → 语义层也拦不住 |
| 人物边界/不造人 | DISCIPLINE L37-38 | JIT 补卡 + 审校 | JIT 会把新名字**主动建档**（补卡也是追认的一种） |
| 抽取忠于正文 | `chronicler.py` L45-50 | 冲突双检（记忆间） | 不查正文↔抽取一致性 → 污染照入库 |
| 境界战力 | R-STATE | `realm_fluctuates` 豁免 | 豁免过度 → 战力失明（上轮已证） |
| 新道具/新设定 | 无（无处登记） | supplement_settings **反向追认** | 自造词变设定，越错越"有据" |

## 附：回答"是否发挥完整作用"的一句话

**机制完整地接入了（八成），但能力被三样东西削掉：数据喂不饱（无米下锅）、每章必达的
纪律被改成 RAG 概率命中、所有"禁止"类指令没有确定性兜底——外加一条会把模型自由发挥
洗白成设定的反向追认通道。修复的重心应从"再调 prompt 文案"转向"补数据 + 加闸门 +
下沉确定性规则"。**
