## 3. 时间预估与节奏

| 项 | 估计 |
|---|---|
| 单章（3 事件 + 编纂 + 润色 + 整章审校） | ~18 分钟 |
| 每事件审校（M3h 新增，3 次/章） | +6–9 分钟/章 |
| 每事件 RAG 查询生成（M3i 新增，3 次/章） | +3–5 分钟/章 |
| 重场戏剧本草稿（×2 生成） | +8–12 分钟/章 |
| **全 20 章** | **8–11 小时** |

建议分 3–4 次跑：`--chapters 6` → `--from-ch 7 --chapters 6` → `--from-ch 13 --chapters 6` →
`--from-ch 19 --chapters 2`，每轮结束看 `run_v5_log.jsonl` 的
`review_blocks / events_revised / lessons_added`。

**两个可调开关**（run_novel_v5.py 里调用 `produce_chapter(...)` 时传参）：
- `event_review=False`：关每事件审校（不推荐，审校闭环是核心）；
- `knowledge_llm=False`：关 RAG 的 LLM 查询生成，退化为事件文本检索（少 3 次/章调用，
  但召回靠关键词蒙——20 章测语义版，别关）。

## 5. 评阅重点（20 章长卷特有的风险）

1. **跨章战力**：20 章下 worldstate/R-STATE 是主要防线——终态看境界链有没有倒退；
2. **暗线是否断**：plot_threads 的 active 线程有没有被后续事件持续关联（affected_threads 分布）；
3. **系统机制一致性**：五五开"绑定→修为一致"的规则每章是否一致（绑定次数/解绑/代价）——审校 lessons 会沉淀这类问题；
4. **20 章记忆量**：fragment_index 碎片数（≈60 事件 + 每事件参与者经历），检索质量是否随量级下降（relevant top-k 是否仍命中）；
5. **人物覆盖度**：25+ 建档人物有多少真出场（可复用 `scan_names.py` 思路）。

## 6. 常见坑

- **单实例锁**：`.v5.lock` 会挡并发启动；若报"another run active"，`ps -W | grep python` 确认无残留进程；
- **长任务运行中改代码不生效**：进程加载的是启动时的代码，改完 bug 要下一轮才吃到——评阅时别把中间态当终态；
- **LM-Studio 显存**：20 章连跑会累积压力，中途模型可能加载失败（可重试；不是代码问题）。
