1. 项目速览

Novelist 是一套把"写小说"工程化为"多 Agent 流水线"的系统：把一句话/已有稿子（Forge 构建层）加工成 bible + 大纲 + 细纲，再经事件循环逐事件生成正文，并以文件工作区为单一事实源（ADR-004/016），配合记忆、索引、确定性一致性闸门、LLM 审校/润色，产出长篇小说成稿并可导出 Markdown/Word。

2. 目录结构与分层

novelist/
├─ src/novelist/
│  ├─ core/       # 内核：llm/embedding/memory/writeback/worldstate/tools/approval
│  │              #       pipeline/orchestrator/director/broadcast/character_factory/
│  │              #       chronicler/polish/timeline/lines/rel_ledger/registry/…
│  ├─ forge/      # 构建层：state(Blueprint)/slots/ask/io_console/seed/ingest/
│  │              #       engine/nodes(递归DFS)/genres/validate/report/review/coherence
│  ├─ providers/  # openai(兼容)/deepseek/lmstudio/fake —— REGISTRY 注册
│  ├─ storage/    # workspace(沙箱+原子写)/checkpoint(双轨快照)/indexdb(SQLite)/models
│  ├─ tools/      # filesys/writing/memory_tools/governance —— build_registry() 装配
│  ├─ craft/      # 题材工艺卡(Genre Pack 运行时)
│  └─ consistency/# rules(确定性规则引擎) + reviewer(LLM 审校, R-SEM)
├─ tests/         # ~110 个测试文件
├─ docs/          # 01–12 + 各批次讨论/排查总账
├─ schemas/       # 实体 JSON Schema（bible/outline/memory/forge/config/policy）
└─ novel_workspace/ # 测试书工作区（不入 git）

核心设计原则：文件即事实源（可版本控制、可人工编辑）→ 引擎/规则做"硬约束"→ LLM 只做"内容生成"、尽量不做"确定性判断"。检索打分教训：关键词路径绝不能走定长哈希向量余弦（碰撞噪声盖过真实信号），改精确 token 集合 + IDF 加权。

4. 主要设计亮点（接手时需理解的机制）

生成
事件循环
细纲 key_events 声明式驱动，逐事件：先忆→装配(接缝/卡/live_state)→生成→审校→回写→润色；截断则续写，key_events 缺失回退整章。
记忆
先忆 / 后纂
MemoryRetriever 双路径检索 + 编纂员抽取事件/状态/时间/约定/线索行，冲突双检 + 章级 trace 可回滚。
一致性
规则引擎做硬闸门
R-TIME/R-STATE/R-TL/R-LEX/R-PWR/R-ITEM/R-CAST… block/warn 分层；决定性问题不交给 LLM。
状态
worldstate 确定性事实源
修为/位置/持物/时间轴/pending/baselines；事件级实然与角色卡双向同步(ADR-013/019/相邻 M3v)。
人物
调度+视角记忆
ADR-020：direction sheet + 事件末多角色视角总结 + 双阈值回读 + 延迟拟题；ADR-021/022 广播选角与角色工厂。
构建
Forge 递归构建
Blueprint+provenance(user受保护) · 商讨协议 · ingest 确定性抽取 · 节点增量落盘 · 预算硬边界 · 快照/rollback。
