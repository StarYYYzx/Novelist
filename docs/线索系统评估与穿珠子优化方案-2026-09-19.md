# 线索系统评估与「穿珠子」优化方案（2026-09-19）

> 触发：真机项目 proj-20260919164352 的卷一细纲出现严重塌缩（ch12 起 72 章只有主角一人出场、
> 3 条主线 0 挂载）。用户要求：① 对照「什么是线索」的文学定义核查现行设计；② 结合 LLM/Agent
> 机制提出优化，思路类比**穿珠子**——一条主线从头贯穿，中间不同位置缠绕不同长度的支线，
> 每到一个位置就看"当前的线里有什么、该拿什么样的珠子"，据此生成产物。
>
> 项目宗旨：**接受多次调用换取更高的文本质量**（含记忆回写等对最终文本有利的内容）。

---

## 一、先厘清概念（依据用户提供的文学讨论）

| 概念 | 定义 | 关键属性 |
| --- | --- | --- |
| **线索** | 串联多段剧情的**持续脉络**（故事的路） | 贯穿性 / 指向性 / 关联性 / 可变化性；长篇 = 1 主线 + 若干支线 + 1 暗线 |
| **伏笔** | 提前埋下的**一次性暗示**（路边标记） | 埋 → 休眠 → 回收即失效；可大量；**依附在线索上** |
| 关系 | 线索是路、伏笔是标记 | 没有线索支撑，伏笔就是散片；没有伏笔，线索推进会生硬 |

长篇线索的四条硬规则（讨论原文）：
1. 支线**阶段性**：有起点、有收尾，**收获必须回流主线**；不得越写越大抢主线
2. 主线可**分节**（逻辑节：目标→阻碍→达成→收获→进入下一节），**节 ↔ 章是区间映射，不是一一对应**
3. 主线可**休眠**（连续若干章写支线），但必须留微小伏笔、且**不得无限期**——到区间检查点必须拾起
4. 控制数量：同时活跃支线 ≤2–3 条

## 二、现行设计核对（文学要求 vs 代码实现）

证据：`schemas/bible/lines.schema.json`、`core/lines.py`（ADR-025）、`forge/nodes.py::_chapter_prompt`、
真机项目 `bible/lines.json` 与 83 章细纲。

| # | 文学要求 | 现行实现 | 判定 |
| --- | --- | --- | --- |
| 1 | 主线唯一 | `kind: main` + "全书恰好 1 条" + 硬校验 | ✅ 有 |
| 2 | 载体类型（物/行动/人/情感/组织/主题） | `carrier` enum 六类 | ✅ 有 |
| 3 | 支线收获回流主线 | `yield` 字段（闭合时必填，注入下卷卷纲） | ✅ 有 |
| 4 | 暗线静默合法 | `kind: hidden` | ✅ 有 |
| 5 | 支线**有长度/起止区间** | —（只有 `target` 远期落点，无起点、无跨度） | ❌ **缺** |
| 6 | 主线**分节 ↔ 章区间** | `volumes.arc`（goal/obstacle/outcome/cost/bridge）+ 章段弧按章序**均分** | 🟡 半有：无"节→区间"映射、无进度期望 |
| 7 | 每章"当前在线的集合" | `chapter_view`：**仅 active 全量** + 冷却告警 + closed 负清单 | 🟡 半有：按 `status` 判定，**不看计划区间** |
| 8 | 伏笔**依附在线上** | `threads.carrier`（载体）+ 卷末审计提名"升级为线" | 🟡 半有：`carrier` 是"载体是什么"，**不是"挂在哪条线上"** |
| 9 | 休眠上限 / 检查点必拾起 | `cooldown_warnings` + 卷末 `volume_audit` | 🟡 只有**告警**，无强制 |
| 10 | 事实开启点 | `lines_present` **需过人审**才生效（`register_pending`→`confirm_pending`） | ❌ **自动流程死锁**（下述实证） |
| 11 | 线索卡必须内容化 | 无内容校验 | ❌ 缺（真机 9 条全是 `main`/`sub1` 占位） |

**结论：ADR-025 的账本设计方向是对的（四级视图、一硬多警、yield 回流都已具备），
但它建模的是"线的状态机"，缺的是"线的时间维度（区间）"与"位置感知"。**

## 三、真机实证：为什么"有线索系统"仍然塌缩

proj-20260919164352（83 章细纲）实测：

| 观测 | 数据 | 说明 |
| --- | --- | --- |
| 线索卡 | 9 条，**全 dormant**，name = `main`/`sub1`/`sub2`/`hidden1` 占位 | 空壳卡，模型无法据此写作 |
| 运行时账本 | `forge/` 下**无任何线账文件** | 从未发生流转 |
| `lines_present` | 83 章中 **63 章为空** | 线几乎没有被使用 |
| 伏笔（pt） | 劫息线挂 **64 章**，茶馆 55、传送阵 51 | **伏笔在用** |
| 主线挂载 | 江辰追查 / 玉虚佩 / 残剑 **0 章** | 三条主线彻底停摆 |

**死锁链（根因）**：
```
ADR-025 设计"章纲 lines_present 过人审 = 事实开启点"
  → /approve-all（UX-1 放行机制）后无人审
  → 线永远 dormant
  → chapter_view 只显示 active 线 → 全书零注入
  → 模型看不到线 → 不产出动作
  → 永远 dormant
```
设计假设"有人在场审"，与放行机制直接冲突——**这是自动化构建路径下的系统性死锁，不是模型问题**。

## 四、「穿珠子」模型（优化设计）

**核心思想**：线是**计划的骨架**（应然），珠是**每章的产物**，位置（章）次第推进；
每到一个位置，系统先算"此刻该在场的是什么"，再决定"该拿什么样的珠子"。

### 4.1 骨架层（蓝图 + 卷纲，全部应然）

| 元素 | 结构 | 与现状关系 |
| --- | --- | --- |
| 主线（唯一） | `kind: main`，book 跨度，`target` = 全书终局 | 已有，补"分节" |
| 主线分节 | 卷 = 大节（已有 arc）；**卷内再分 2–4 小节**，每节带 `[start_ch, end_ch]` + 目标/阻碍/结果 | **新增**（L1） |
| 支线（有限长度） | `kind: subplot` + **`planned_span: {start_ch, end_ch}`** + `yield`（回流目标，指向主线某节） | **新增区间字段** |
| 暗线 | `kind: hidden` + **`reveal_points: [章位]`**（计划露头/揭示） | **新增** |
| 伏笔（pt） | `carrier` + **`parent_line`（挂在哪条线）** + **`payoff_window: {start_ch, end_ch}`** | **新增两字段** |

> "不同长度的支线" = `planned_span` 的可变长度；"缠绕在不同位置" = span 的起止章位。

### 4.2 位置层（每章生成前，**确定性计算，零 LLM 调用**）

新纯函数 `bead_view(ledger, threads, scale, vol, ch) -> BeadPlan`，输出四类清单：

```
on_stage      = 主线（恒在）+ span 覆盖本章的支线 + 到 reveal 点的暗线
                + payoff 窗口含本章的伏笔
opening_due   = span.start_ch == ch 的支线（本章必须 open）
closing_due   = span.end_ch == ch 的支线（本章必须收束 + 登记 yield）
overdue       = 超出休眠上限未动作的线 / 超出 payoff 窗口未回收的伏笔（点名强制）
```

这套计算回答的正是用户的"看着当前的线里包括什么"——**它替代现在"只给 active"的口径**。

### 4.3 产物层（本章的"珠子"）

| 珠子类型 | 载体 | 约束 |
| --- | --- | --- |
| 主线节推进 | 主线 lines_present `advance` | 主线休眠 ≤ N 章（N 由节跨度定） |
| 支线开 / 推 / 收 | 支线 lines_present `open/advance/close` | 收束章必须登记 `yield` 回流 |
| 暗线露头 | 暗线 `flicker/advance` | 按 `reveal_points` |
| 伏笔埋 / 收 | `threads_involved` + planted/returned | 回收窗口到期未收 → overdue |
| 日常珠 | 不挂线的事件 | 允许，但**必须登记**；不得连续超过 M 章无主线动作 |

### 4.4 写入层（双轨开启，解开死锁）

| 模式 | 开启方式 |
| --- | --- |
| 交互（人在场） | 保留 `pending → 人审`（现状） |
| 自动构建（approve-all / 无人值守） | `lines_present` **直接生效**（`apply_chapter_actions`），全程留痕进 transcript，可回放 |

### 4.5 守卫层（机械可验 → 进 doctor 预检）

1. 主线连续 N 章零动作 → **block**（休眠上限）
2. 支线 `span.end_ch` 已过仍未闭合 → **block**（超期未收束）
3. 支线闭合时 `yield` 为空 → **block**（收获未回流）
4. 活跃支线 >3 → warn（已有）；TAIL 阶段开新线 → deny（已有）
5. 伏笔超出 `payoff_window` 未回收 → warn
6. 空壳卡（`desc`/`carrier`/`planned_span` 缺失）→ **拒绝入账**

今天这 6 条里前 5 条一跑就能把塌缩全报出来。

### 4.6 多调用换质量（契合项目宗旨）

| 时机 | 额外调用 | 产出 |
| --- | --- | --- |
| 每节边界（每 20–30 章） | **线账体检 agent**（`run_evidence` 只读，复用现有工具面） | overdue / 失衡 / 建议收束的支线清单 |
| 支线收束章之后 | **回流结算**一次调用 | 把支线收获写成主线状态 + 账本更新（`yield` 内容化） |
| 伏笔回收章之前 | **铺垫检查**一次调用（可选） | 确认前置提及足够，不足则补一处 `flicker` |

## 五、与既有 ADR 的关系

| ADR | 关系 |
| --- | --- |
| ADR-025 线索子系统 | **不推翻**：四级视图、一硬多警、yield 回流全部保留；本方案补"区间 + 位置计算 + 自动生效" |
| ADR-011 应然/实然 | 骨架层（span/target/yield）为应然；status/progress/last_seen 为实然——沿用 |
| ADR-013 事件实时回写 | 珠子落地后由 Chronicler 确认，与既有回写链一致 |
| ADR-026 承诺账本（covenant） | **需划界**：covenant = 对**读者**的承诺（伏笔/约定）；`yield` = 支线对**主线**的收获。二者现无交集说明，建议在文档中写明分工 |
| ADR-036 常驻对话 Agent | 主线/支线的裁决、超期线的处置走对话 agent 的 danger 工具（第二版） |

## 七、待拍板

1. **支线区间由谁登记**：卷纲节点（推荐，卷内视角最全）/ 蓝图 book 节点

5. **卷一重建**：L1 落地后用 `roll-window` 从 ch12 起重建（约 70 次调用）作为验收
