## A. 人物关系/行为语义层（本次 discussion 延伸，人物一致性栈核心）

- **A1 [开] 五五开系统缺 canonical 条款（P0-A 剩余）**
  bible 的 set:wuwu / 叶岚卡关系只写"寄生宿主、互相利用"，无**绑定时长 / 接触条件 / 解除条件**；模型被迫自创"碰衣角=短暂绑定、解绑回落"（L119 内部自洽但非官方语义）。
  修法（2026-09-03 已定稿，ADR-024 T1 + unknowns 闭环，待编码）：走 enrich/setting 补喂一条 wuwu 铁律（人工确认通道），mechanic 从一句话升级为"条款子槽"（绑定条件/时长/解除/限制/反噬），或直接加 worldview.rule。
- **A2 [开·设计已定稿 ADR-023（2026-09-03），待编码] relationships 事件性语义与实时刷新**
  `type` 是一句话关系状态，文字可隐含"过去事件"（救命/婚约/三年杂役）。三类未区分：状态性（无需场景）/ 事件性·有据（histories 可溯源）/ 事件性·无据（从未发生、也无排期）——无据型注入后是幻记温床（ch6 L93 引"从未发生过的谈话"为同型机制）。
  已拍板方案（ADR-023，D1/D2/D3）：视角事件不写 bible 卡（N4 log 留 memory，卡只渲染状态行 ≤1 条）；**新建实然关系账本 `memory/relationships.json`**（按 pair 键，事件末用 N4 delta 纯确定性聚合，state/trend/双方认知分开存/last_event 溯源）；显著翻转→阈值触发"关系修订提案"走 **enrich pending 人工 allow**（D3-b）；关系视图层 RelEdge 按需投影（三类边带 kind/source/time，不建知识图谱系统）。
- **A3 [开] enrich 闸门只查结构不查语义 + 输入不看细纲**
  `check_proposal`（character_enrich.py:121-165）只查串卡/自指/长度/age；"不与已发生事实冲突"是 prompt 软约束。且 `_propose_one` 输入无**未写章节细纲**→ 轴B（应然×细纲）冲突无 ahead-of-time 消解。
  修法：enrich 输入补细纲要点，或 proposal 闸门接 RAG 比对（低成本高价值）。
- **A4 [开] ADR-022 工厂草卡不给实然历史**
  `character_factory._PROMPT`（:253-269）只给现有角色名册，新卡 relationships/behavior_rules 由 LLM 现编，无任何历史约束——比 enrich 更弱。且广播 needs 的 `why_existing_fail` 从未被程序消费（见 B3）。
  修法：工厂 prompt 注入相关实然摘要 + need 语义；产卡后过 enrich 同款语义闸门。
- **A5 [已闭环] M3r 26/26 补喂 + 同 target 覆盖式合并**（commit 836877e/6d6ceef/b2a2171）；全部卡 `provenance.origin=enrich`（原卡无 provenance 被统一盖上，历史来源不可辨——若在意可后续补 seed 溯源，非阻断）。

## C. 时序与事实同步

- **C1 [已闭环 2026-09-03] worldstate.time 未随章推进（probe 发现②）**
  实测 yelan3 `time.now=3`：ch1-5 正文无任何跨天表述、ch6 含 3 处"三日后"并推至 day3，
  与正文自洽（timeline tl:1-3 的"784 年春夏"是 ingest 旧历法数据，与天数轴不同源造成错觉）。

  正文不写 → 时间停滞 → pending.due 永不逼近 → 时间承诺（闭关三月/三年之约）长卷必忘。
  修复（用户拍板 **D 方案**，commit 待）：① EXTRACT_PROMPT 时间行从可选改**必答判断**
  （每段必须 1 条：有跨度写 +N日 / 没跨度写「时间：同日」/ 回忆写「时间：闪回」，禁止编造）；
  ② `_apply_time` 修 dt=0 事件文案（原恒为误导性"时间推进 0 日"→"同日内推进"）；
  ③ 章末审计落 now（`_write_generation_audit` 加 world_now，md + audit_log）。
  测试：同日不推进 / prompt 必答约束锁文本 / audit 带 now / m10+m19+writeback+m4 117 passed。
  遗留：章末确定性兜底（模型仍不答时）未加——同日已是安全默认，不推进不会更糟。
- **C2 [开·能力面已定稿 ADR-023 D1 补充，待编码] 细纲生成用"前章计划态"而非正文实然**
  chapter prompt 的 prev = 前章 gist（细纲），非前章实际成稿；roll 的实然（末 3 章 plot_events/世界现状）只注 volume 级。正文写偏后（如 ch6 标题没按细纲走）下一章细纲感知不到 → 细纲与落盘正文漂移。
  修法（用户主张：负责策划情节的 Agent 应能查询具体事件经过）：策划低频决策点接确定性查询接口读实然事件（plot_events + histories + timeline 序），不靠 prev 计划态；正文高频生成仍走紧凑前情注入。

## D. 细纲/构建层（本次 forge prompt 审计）

- **D1 [开] chapter 细纲 prompt 无"情节工艺"硬要求**
  只有最小契约：key_events 2-3 个"含动作与结果"一句话 + turns + 衔接前章。冲突推进/悬念/张力/伏笔回收**无强制输出项**（threads_involved 可空）；chapter_rhythm 节奏表只注入不约束结构。产物是"事件清单"不是"情节设计"；剧情工艺实质由正文 prompt 承担（orchestrator.py:118"冲突要给足"、:899"点出最有戏一点"）。
- **D2 [开] beat 节点近死分支**
  beat（重场戏拍级 4-8 拍）只在 chapter 返回 `decide=expand+children` 时触发，但 chapter 输出协议根本没要求 decide 字段（_parse_node_reply 默认 done，nodes.py:96-98）→ 几乎永不触发。需拍板：重场戏判定改确定性规则（如含"大比/决战/告白"关键词）并在 chapter prompt 加 decide 协议。
- **D3 [已闭环 2026-09-03] chapter/volume prompt 协议与解析不一致（真实缺陷）**
  `_chapter_prompt`/`_volume_prompt` 要求模型输出**顶层** title/key_events…（无 `artifact` 包裹、无 decide），而 `_parse_node_reply` 只取 `data["artifact"]`、`_apply_chapter` 只读 `node["artifact"]`（nodes.py:748）。实证（scripted 严格照 prompt 输出）：落盘细纲变占位 `title="第 1 章"、key_events=["第 1 章主线推进"]`。测试脚本全用 artifact 包裹喂入故从未暴露。
  修复（方案 B，用户拍板）：`_parse_node_reply` 兼容顶层字段——有 `artifact` 键用之；无则剔除协议元键（decide/reason/children/open_questions）后顶层整体当 artifact；返回 `has_shell` 标记，裸产物不再误报"未给 reason"。产物真空时占位 warning 文案区分"模型空回复"与"仅 key_events 空"。探针转正为 `tests/test_d3_protocol.py`（裸 JSON 完整落盘 + 无 reason 误报 + 带壳不回归）。
  遗留（未做，另行评估）：空产物是否升级为"引擎重试"而非占位兜底（当前保留占位作为最后防线）。
- **D4 [决策] 卷 1 build / 卷 ≥2 roll 细纲链路真机验证薄弱**
