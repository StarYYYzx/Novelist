## 2026-09-11 新发现（fastembed 本地 embedding 接入后）

> 背景：9-07 批次引入 `LocalEmbedding`（fastembed/ONNX，nomic-embed-text-v1.5，768 维）替代已停用的 LM-Studio；
> 本机首跑全量出现 3 失败（`test_local_embed_real_vectors` / `test_m3_full_pipeline` / `test_m3_memory`），
> 根因定位为下述两条。**当前已通过"绕过沙箱代理预下载模型"恢复全绿（966 passed）**，但两条缺陷仍在。

- **P-FE1 fastembed 缓存落 Temp + 下载被代理拦截（环境脆弱，P1）** —— 现象：模型缓存在
  `%TEMP%/fastembed_cache`（Windows Temp 会被清理/磁盘清理工具回收）；缓存缺失时首次调用需下载
  ~550MB，沙箱代理下 httpx 走代理直接 502（`httpcore.ProxyError: 502 Bad Gateway`）。
  `[实测]` 直连 hf-mirror 200 OK，走代理 502；预下载需
  `https_proxy= http_proxy= HF_ENDPOINT=https://hf-mirror.com HF_HUB_DISABLE_SYMLINKS=1`（Windows 上
  HF symlink 落位会失败，必须复制模式），下载后 blob 547MB 完整、二次加载正常（768 维）。
  修复方向：① `LocalEmbedding` 默认 `cache_dir` 指向工作区持久目录（如 `novel_workspace/.model_cache`）
  而非 Temp；② 文档明示内网/离线部署需预置缓存 + `HF_HUB_OFFLINE=1`。
- **P-FE2 LocalEmbedding 惰性降级穿透（P1，与注释承诺矛盾）** —— 现象：`make_embedding("local"/"auto")`
  的降级 try/except 在**构造期**，而 `LocalEmbedding` 设计为**惰性加载**（`__init__` 不触底座，首次
  `embed()` 才 `_ensure_backend()`）——模型下载/加载失败时抛 `ProviderError`，构造期 except 永远捕获不到
  （注释却写"模型下载失败/损坏等一律走降级"，实现与承诺不符）。
  `[实测]` `test_m3_full_pipeline` 跑真实 CLI 命令 exit_code=1 + `ProviderError: fastembed load failed`；
  无模型环境 CLI 直接崩，而非降级关键词检索。
  修复方向：① `_ensure_backend()` 失败时实例内降级（转交内部 KeywordEmbedding 并改实例 `kind`），
  或 ② `make_embedding` 返回前做一次预热探针（try 一次 `embed(["probe"])`，失败则返回 KeywordEmbedding）；
  ③ 同时给 `test_local_embed_real_vectors` 加"模型可用性探测"，不可用则 `pytest.skip`（避免无网环境必红）。
