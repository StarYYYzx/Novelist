# Prompt 组装结构审计：每个环节是否拿到了它该拿的信息

> 审计日期：2026-09-12
> 审计对象：全部 31 处 `LLMRequest` 的**输入侧**——每处 prompt 注入了什么、缺了什么
> 与 `docs/prompt审计-2026-09-12.md` 的分工：那份审**文本结构与成本**（位置、重复、缓存、长度）；
> 本报告审**信息覆盖**（这个环节靠什么做判断，它实际看见了什么）。
> 方法：代码静态读取 + 真实 bible 离线渲染 + 真实产物统计（80 条审校 lessons / 56 条 glossary / 227 条禁令词）。

---

## 总判定

**骨架是完整的：一条「细纲 → system prompt → 章节 goal → 事件 prompt → 审校 → 润色 → 编纂回写」的链上，
信息是逐级**追加**的，没有环节是空手工作的。** 事件级 prompt 尤其厚（18 类注入块 + RAG 五类检索 + 实然状态钉死层）。

问题出在**两头**：

1. **上游细纲层缺世界观基座**——它决定"这一章发生什么"，却看不到境界体系与世界铁律（P1-1）；
2. **下游审校层三处信息被窄化**——它要判"有没有错"，却只看到正文尾部 3000 字、细纲前 800 字，
   且有一个维度名与解析白名单对不上，导致该维度**静默失效**（P1-2 / P1-3）。

另有 4 项低危缺口（P2）。同时确认 5 处做得对、不要动。

| 级别 | 数量 | 一句话 |
|---|---|---|
| **P1** | 3 | 细纲层不含世界观基座；审校只看正文尾 3000 字且取证路径不含章文件；审校 `gist[:800]` 比生成侧窄 3 倍 |
| **P2** | 5 | 审校「时间线与因果」维度名不在解析白名单 → 归"其他"（实测证实）；「伏笔」维度 CATEGORIES 有、prompt 无；`_bible_brief` 无 glossary/工艺卡；检索查询只看事件前 200 字；设定补充只看事件后 800 字 |

## 二、逐环节详判

### 2.1 P1-1 · 细纲层不含世界观基座（上游最硬的信息缺口）

**证据**：`forge/nodes.py:472 _chapter_prompt` 的函数体内，关键词扫描结果——

```
worldview      0 次
power_system   0 次
levels         0 次
rules          0 次
```

而**下游的正文 system prompt 有全部**（`context.py:201-217`：境界体系 + 铁律 + 文明 + 体系 + 境界波动），
**同级的人物工厂也有**（`character_factory.py:259-260`：`境界表（power.level 必须出自此表）`、`宗门/势力名册`）。

**后果**：决定"这一章发生什么"的那一层，关于世界规则只有**角色卡里带出来的 `power.level` 一条间接证据**。
`docs/prompt组装结构审计` 提到的 fame5 开局修为不一致（细纲"炼气三层废柴" vs 正文"九层压线"）
正是这个缺口的表现面：细纲层没有境界体系表可对照，正文层有。

**修法**：在 `_chapter_prompt` 的 user 模板里加一个 `【世界观基座】` 块（境界体系 + 铁律 + 世界概要），
数据源与 `_sibling_block`（`nodes.py:649`，已有 `worldview.levels/rules`）同源，**纯增量注入，不改规则**。
成本：约 150–300 字/章。

### 2.2 P1-2 · 审校只看正文尾部 3000 字，且取证路径不含章文件

**证据**

```python
# consistency/reviewer.py:120
LLMRequest(messages=[LLMMessage(role="user", content=prompt + text[-3000:])], ...)
# consistency/reviewer_agent.py:82
) + text[-3000:]
# consistency/reviewer_agent.py:105 _evidence_pointer
"\nbible/characters.json · bible/worldview.json · memory/plot_events.json"
```

**影响分两路**：

| 路径 | 影响 |
|---|---|
| **事件级**（`orchestrator.py:2126`，主链路） | 影响小——审的是单事件片段，通常 <3000 字。但重场戏经拍展开（`_generate_beats`）后可超 3000 字，会丢头 |
| **章级**（`reviewer.py:147 review_chapter_file`） | **明确丢头**——该函数把整章正文交给 `review()`，而默认 `scope` 是「本次审读的是完整一章」，正文却只传了尾部 |

而且 agentic 审校的取证指引只给 bible 与 memory 路径，**不含章正文文件** → 证据环想补读头部也无从下手。

**修法**：`review()` 按 `scope` 决定窗口——章级走 head+tail（复用 `chronicler._chapter_window` 的成熟模式，
它已经因为"tail-only 漏掉章头时间行"被修过一次，同一坑）；`_evidence_pointer` 追加当前章文件路径。

### 2.3 P1-3 · 审校的细纲视图比生成侧窄 3 倍

**证据**：生成侧 `context.py:304 gist_max_chars=2400`（且注释记载 1200→2400 是因为"超长细纲尾部要点模型看不见"）；
审校侧 `reviewer.py:116 gist=gist_text[:800]`。

**后果**：审校维度里就有「**细纲未覆盖**」——用一个 800 字的细纲视图去判 2400 字细纲有没有被落实，
判定基础与生成侧不一致。实测 80 条审校 lessons 里「细纲未覆盖」占 **17 条（21%）**，
是第二大类别——这个数字有多少是"审校看不见细纲尾部要点"，无法从现有数据区分，
但**信息基础不对等是事实**。

**修法**：`gist_text[:800]` → 与生成侧同源（`GIST_MAX_CHARS` 共享常量）。

### 2.4 P2-1 · 「时间线与因果」维度名不在解析白名单 → 该维度静默失效（已实测证实）

**证据**（本次实测，机械可复现）

```
REVIEW_PROMPT 给出的维度：… - 时间线与因果：事件顺序、因果链是否自洽 …
CATEGORIES（reviewer.py:28）: (…, "时间线", …, "伏笔", "其他")

Reviewer._parse(obj, "block | 时间线与因果 | 描述 | 建议")
  → category = '其他'        ← 维度名对不上白名单
Reviewer._parse(obj, "block | 时间线 | 描述 | 建议")
  → category = '时间线'
```

**真实产物佐证**：工作区全部 `review_lessons.json` 共 **80 条**，category 分布为

| 战力越级 | 设定矛盾 | 细纲未覆盖 | 事实前后矛盾 | 称谓失当 | 其他 | 人设漂移 | **时间线** | 伏笔 |
|---|---|---|---|---|---|---|---|---|
| 22 | 18 | 17 | 16 | 4 | 2 | 1 | **0** | 0 |

——prompt 里列为七个维度之一的「时间线」，**在 80 条真实产出里一次都没出现过**。

**后果**：时间线类问题仍会被报出（归"其他"），不丢问题；但**分类统计失真**，且
`_append_lessons` 的去重键 `_key = f"{category}|{issue[:30]}"` 会因分类漂移而改变 → 可能重复入库。

**修法**：把 prompt 里的维度名统一为 `时间线`（或把 CATEGORIES 扩为包含 `时间线与因果`）。一行级改动。

---

### 2.5 P2-2 · 「伏笔」维度：CATEGORIES 有、REVIEW_PROMPT 无

`reviewer.py:13` 的模块 docstring 明确宣称审校职责之一是「**伏笔是否按预期推进**」，
`CATEGORIES` 也留了 `伏笔` 位；但 `REVIEW_PROMPT`（`reviewer.py:45-57`）列的七个维度里**没有伏笔**，
并且明写「维度只能是上述七项之一」。→ 宣称的能力与 prompt 要求不一致（伏笔实测 0 条）。

**修法**：把「伏笔：本章是否该推进/回收某条线而未推进」补进 REVIEW_PROMPT 的维度列表
（注意与 ADR-025 线索卡的分工：线索卡管"必须推进"，审校管"漏了没有"）。

### 2.6 P2-3 · `_bible_brief` 缺 glossary / 工艺卡 / 境界波动

`reviewer.py:71 _bible_brief` 只给：境界体系、铁律、主角（名+性别）、人物卡（名/性别/境界/阵营/性格）。

**缺**：`glossary`（专有名词固定写法）、`craft_cards`（题材硬规范）、`realm_fluctuates`（境界波动）、
`modern_words_exempt`（现代词豁免表）。

**最值得注意的是 glossary**：**专有名词写法在整条链上没有执行侧校验**——
生成 system prompt 里声明了（`context.py` 专有名词行）、R-LEX 规则引擎不查（`rules.py:92` 只查 forbidden/modern）、
审校不查（无 glossary），润色的 system prompt 透传了生成侧那句声明但没有校验。
即"写法必须固定"目前**只有要求、没有检查**。

**修法**：`_bible_brief` 追加 glossary 行；并在 R-LEX 里加一条轻量检查（术语出现时写法是否与 glossary 完全一致）。

### 2.7 P2-4 / P2-5 · 两处窗口过窄

| 位置 | 现状 | 影响 |
|---|---|---|
| `knowledge.py:241` | `QUERY_PROMPT.format(ev_text=ev_text[:200])` | 检索查询只由事件**前 200 字**生成；长事件的检索意图不全 → 召回偏 |
| `orchestrator.py:680` | `_supplement_settings`：`ev_text[-800:]` + `known[:120]` | 新设定提案只看事件尾部 800 字；已知词表截 120 条 |

两处都是"增强层/提案层"，失败不阻断（有确定性兜底），故 P2。

## 四、建议执行顺序

**批次 2（与 prompt 结构重排合并做，需一轮真机对比）**
1. **P1-1** `_chapter_prompt` 补【世界观基座】——改的是上游，影响面最大，必须真机跑 3–5 章对比细纲质量

6. **P2-4 / P2-5** 两处窗口放宽
