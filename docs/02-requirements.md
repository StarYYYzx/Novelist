# 02 · 需求规格说明书

> 本文档定义系统的用户画像、用例、功能需求（FR）与非功能需求（NFR），并给出可验收的准则。编号 ID 供后续设计文档与测试用例引用。

## 1. 用户画像

| 角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| U1 连载作者 | 网文写手，产出节奏快，日更数千字至数万字 | 批量组稿、一致性自动保障、人工审批点 |
| U2 结构化创作者 | 重视世界观与人物的严谨性 | 设定圣经精细维护、伏笔管理 |
| U3 团队运营 | 管理多本书/多作者 | 批量管理、进度与质量统计 |
| U4 普通读者（间接） | 消费最终文本 | ——（非直接用户，但正确性目标服务于其体验） |

## 3. 功能需求（FR）

按模块分组。

### F1 创作流程编排
- F1.1 系统以**流水线状态机**管理工序：`立项 → 世界观 → 大纲 → 细纲 → 正文 → 审查 → 记忆编纂 → 疑似完成`，允许在任一工序进入 `修订` 并回流。
- F1.2 工序由主编剧 Agent 主导，可派发对应子代理执行并收集结果。
- F1.3 每个工序的运行可中止、可续跑、可回滚到检查点。
- F1.4 正文 **审查通过后、发布前**，须经过**记忆编纂**收尾工序（ADR-013）。

### F2 设定圣经（单一事实源）
- F2.1 维护以下集中数据结构：`世界观`、`人物卡`、`力量/设定体系`、`地点/地图`、`时间线`、`伏笔`、`词汇表/文风约束`。
- F2.2 任一修改须记录版本与被影响章节索引，供一致性检查定位。
- F2.3 支持从正文反向**提取/顺延**维护设定（例如新登场人物自动建档）。
- F2.4 **设定圣经（权威·应然）与记忆层（事实·实然）分离管理**，二者互相引用不混淆（ADR-011）。

### F3 正文生成
- F3.1 正文生成异步化，支持单章或多章批量并行，受并发上限与 token 预算约束。
- F3.2 生成过程写入创作快照（草稿），仅在人工或自动批准后落为正式章节。
- F3.3 保持同一本书统一的文风（角色语气、叙述节奏、禁用词）。
- F3.4 **写入前置"先忆"**：文字匠/审校师在任务开始时经 `query_memory` 召回相关人物近况与事件（ADR-011/5.5）。
- F3.5 重场戏可启用**角色试演**：按需派发演员 Agent 产出角色视角片段，再整合为正文（UC-16，ADR-012）。

### F4 一致性保障
- F4.1 提供**规则检查**（字段值、引用完整性、时间线单调）与**LLM 语义检查**双层校验。
- F4.2 输出结构化告警：`级别(block/warn)`、`涉及对象`、`说明`、`建议修订`。
- F4.3 伏笔登记/回收状态机：`未触发 → 已埋 → 待回收 → 已回收`，支持逾期提醒。
- F4.4 **记忆沉淀双检**：新增记忆须经规则 + 语义双检，冲突则回退提请人工，不静默入库（ADR-013，UC-18）。

### F5 Agent 与 LLM
- F5.1 以**单主编剧 + 按需子代理**拓扑运行（详见设计文档），不支持无边界网状自由通信。
- F5.2 内置一组**命名子代理**（世界观构建师、大纲师、文字匠、审校师、伏笔监理、检查员、**记忆编纂员**），可由主编剧派生；并支持运行时按需生成**角色演员**子代理。
- F5.3 LLM 通过**适配器**接入，接口统一、可运行时切换 Provider / 模型（含 Embedding 能力）。
- F5.4 结构化输出契约化（JSON Schema），结果不符时自动重试或降级。

### F6 权限与安全
- F6.1 危险操作（删除章节/批量改写/发布/覆盖设定）走**权限门禁**，默认需要人工确认，可配置 `allow/deny/ask` 三态。
- F6.2 输出内容经**敏感词与安全过滤**；大模型调用入出参记录审计日志。
- F6.3 不向 LLM 暴露除项目工作区之外的本地文件，路径访问受沙箱约束。

### F7 可观测与存储
- F7.1 记录全量**事件日志**（每次 Agent 思考摘要、工具调用参数与结果、token 用量）。
- F7.2 支持**检查点**（项目 JSON 快照 + 正文文件），实现恢复与回滚。
- F7.3 提供里程碑式**工作区目录规约**，文件即状态，便于人工查看与 Git 版本管理。

### F8 交付与集成
- F8.1 导出功能：单章/整书/指定卷的纯文本或 Markdown 发布包。
- F8.2 统计功能：字数、章节数、token 成本、一致性告警分布、伏笔状态。
- F8.3 提供对外编程接口（API 或 CLI），供脚本与上层工具调用。

### F9 记忆检索（Memory + RAG，ADR-011）
- F9.1 记忆层沉淀**人物经历史、剧情事件流、关系变化**，并重建可检索的 **RAG 索引**（语义 Embedding + 关键词兜底）。
- F9.2 提供 `query_memory` / `get_character_history` / `get_plot_events` 检索，返回带来源定位与圣经引用的摘要命中。
- F9.3 检索结果默认以**摘要**注入上下文，可按需取原文，控制 token（04§5.8）。
- F9.4 检索能力必须具备降级路径（无 Embedding Provider 时退化为关键词索引，仍可用）。

### F10 角色试演（Actor，ADR-012）
- F10.1 重场戏可按需派发**角色演员**，上下文 = 人物卡 + 本角色经历记忆摘要 + 场景剧本 + 文风约束。
- F10.2 演员产出 `character_take` 试演片段（第一人称/该角色视角），写入临时 takes 目录。
- F10.3 演员**数据隔离**：只能读本人物卡与其经历记忆、只能写自己的 take，不得读写他人未授权记忆或正文章节（防串味）。
- F10.4 文字匠负责把多角 take 整合为第三人称正文并仲裁 take 间冲突。

### F11 记忆编纂（Chronicler，ADR-013）
- F11.1 章节审查通过后进入**记忆编纂**收尾：提炼事件进展、人物经历变化、关系变化、伏笔流转、时间推进并写入 `memory/`。
- F11.2 每条记忆记录**来源定位、引用的 bible 实体 id、版本**。
- F11.3 新增记忆经**冲突双检**（规则 + LLM 语义）；冲突者回退并提请人工仲裁（UC-18），不静默入库。
- F11.4 编纂完成后触发 RAG 索引增量重建，供后续"先忆"。

### F12 并行批次的剧情衔接（ADR-011/04§4.2）
- F12.1 只有**因果独立**的多章才可同批并行；存在因果先后/强依赖的章强制串行或错批。
- F12.2 一批启动前固化 `batch_base` 记忆基线，批内所有草稿基于同一基线写作，避免批内互相追赶。
- F12.3 每批收尾统一记忆编纂，新形程沉淀为后续批次基线；整批提交前做**批次级一致性门禁**（时间线单调、人物状态、伏笔流转整体校验）。
- F12.4 批内若出现影响其他章的转向，受影响章延迟转正并在下一批基线中回流重写。

### F13 受控围读会（ADR-014，群聊例外）
- F13.1 重场戏可选开启**围读会**：主持人（主编剧）驱动 N 个演员经 `join_scene/say_line/leave_scene` 交锋。
- F13.2 围读会具备**明确结束判据**：全体离场 / 达轮次上限 / 话题收敛 / 预算超时 / 异常强制收场（任满即收）。
- F13.3 围读会**按场景隔离**：参与者不可读他人未授权记忆、不可场景外互调、主持人可随时收场（不失控回退为无界群聊，ADR-001）。
- F13.4 谈话纪要并入 `character_take`，供文字匠整合成正文。

### F14 LLM 输出被审核拦截（ADR-015）
- F14.1 Provider 层识别 `MODERATION_BLOCKED`，其上游处理链：改写重试 → 切换 Provider → 人工介入 → 挂起不静默跳写。
- F14.2 正文/对白前运行**敏感词预检**降低命中率。
- F14.3 拦截事件落审计与统计；被挂起片段不清零，待人工后再继续。

## 4. 非功能需求（NFR）

| 编号 | 类别 | 需求 | 验收指标（示例） |
| --- | --- | --- | --- |
| NFR-1 | 性能 | 批量并行生成 | 单机并发 2–4 章/批，章节生成时间可接受（受模型速度限制） |
| NFR-2 | 可扩展 | Provider 插件化 | 新增一个 Provider 后端不改动核心代码，仅实现适配器接口 |
| NFR-3 | 可靠性 | 崩溃恢复 | 任一步骤中断后可从最近检查点恢复且不丢已批准成果 |
| NFR-4 | 一致性 | 全书自洽（含记忆） | 一致性规则检查通过率 >= 99.9%；语义检查不引入设定矛盾；记忆沉淀不与既有记忆/bible 冲突 |
| NFR-5 | 可观测 | 操作留痕 | 每次 LLM 调用、工具调用均有审计日志与 token 计量（含记忆读/编/检索） |
| NFR-6 | 安全 | 权限与沙箱 | 无人工授权不执行任何删除/覆盖/发布；Agent 无法访问工作区外路径；演员只读本人物卡与自身经历 |
| NFR-7 | 可维护 | 结构与文档 | 核心模块边界清晰、接口契约化，配套本文档集 |
| NFR-8 | 跨平台 | Windows 优先 | 核心在 Windows/Linux/macOS 可运行，路径与进程处理跨平台 |
| NFR-9 | 成本 | Token 可控 | 每章有预算上限，超预算阻断并提示；检索按 top_k 剪枝控制注入量（防止失控消耗） |
| NFR-10 | 可评测 | 质量可度量 | 提供评测集与评分维度（文风保持、一致性、情节逻辑、记忆保真、人设保真），可离线跑分 |
| NFR-11 | 记忆 | 检索可用与保真 | 按人物/事件/关系提问能命中相关史实（命中率、NDCG 目标见 09§3）；记忆沉淀无幻觉/无矛盾 |
| NFR-12 | 人设 | 角色一致生动 | 演员试演片段与人物卡 + 近期经历无明显不符；多角对手戏整合后上下文连贯 |
| NFR-13 | 并行 | 批量剧情衔接 | 并行批次以基线固化，整批一致性门禁通过；批内转向触发受影响章回流不遗漏 |
| NFR-14 | 合规 | 审核拦截友好 | 被供应商审核拦截时不产生缺章/静默跳写；命中后经改写/切换/人工流程恢复，拦截留痕 |

## 5. 验收标准摘要

- **A1**：给定一句创意，系统可产出包含世界观、大纲、X 个完整章节的连载成果物。
- **A2**：跨章节的人物属性/时间线/伏笔无矛盾（规则层零失败）。
- **A3**：无论对接云 API 还是本地模型，同一工作区内项目可完整跑通一次创作流水线。
- **A4**：在一次随机断电（进程 kill）后，可从检查点恢复并继续到完成。
- **A5**：所有涉及覆盖/删除/发布的操作，在默认配置下均需人工确认方可执行。
- **A6**：产出的发布包通过敏感词过滤，且包含字数与成本统计报告。
- **A7（记忆自洽）**：编写第 N+1 章时，能经记忆检索召回前几章埋下的待回收伏笔与人物近况，且无内容矛盾（NFR-11）。
- **A8（人设保真）**：角色演员试演片段与人物卡及近期经历无明显不符；对手戏整合后连贯（NFR-12）。
- **A9（并行衔接）**：一批并行的章节转正后，晚批章节能经由记忆检索感知早批章节产生的关键剧情，批次级一致性门禁通过（NFR-13）。
- **A10（审核拦截）**：模拟云 API 拒答/审核错误时，系统经改写/切换/人工路径恢复，不产生缺章或静默跳写（NFR-14）。
