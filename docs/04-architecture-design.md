# 04 · 总体架构设计

> 承接选型结论（03），描述系统的**整体结构**：逻辑分层、C4 视图、运行拓扑、关键运行机制与时序。Agent 层细节与数据/接口细节分见 05/06/07。

## 1. 设计原则

1. **唯一中枢**：主编剧 Agent 是唯一决策中枢，子代理无全局永久记忆，只能经工具访问工作区。
2. **文件即记忆**：一切跨 Agent 的长期状态落在小说工作区，会话上下文只保留"摘要 + 引用"。
3. **工具即边界**：Agent 的唯一动作手段是调用受控工具；权限门禁、审计日志、沙箱都在工具层收口。
4. **可观测为默认**：每个 Agent 动作、每次 LLM 调用都有事件记录，可完整重放。
5. **降级不塌方**：模型能力不足（如不支持工具调用）时走退化为"纯文本 + 后解析"路径，而非中断全书。
6. **人工优先**：不可逆操作一律需门禁确认；任何节点可暂停、可编辑中间产物后再继续。

## 2. 逻辑分层（Layered View）

```
┌──────────────────────────────────────────────────────────────┐
│ 交互层  UI / CLI / API 门面        (F8, 对外集成)              │
├──────────────────────────────────────────────────────────────┤
│ 编排层  流水线状态机 · 调度 · 检查点 · 权限门禁 · 预算控制        │
├──────────────────────────────────────────────────────────────┤
│ Agent 层  主编剧 Agent(Orchestrator) · 命名子代理 · 工具注册表   │
├──────────────────────────────────────────────────────────────┤
│ 执行层  工具集(Tools) · 一致性规则引擎 · 事件总线 · 审计日志      │
├──────────────────────────────────────────────────────────────┤
│ 存储层  小说工作区(文件系统) · 检查点快照 · 配置/密钥              │
├──────────────────────────────────────────────────────────────┤
│ 模型层  LLM Provider 适配器(云 API / 本地) · 降级策略            │
└──────────────────────────────────────────────────────────────┘
```

各层职责：
- **交互层**：把用户意图（起点创意、审批决策、参数偏好）注入编排层，并把状态/进度/产物呈现给用户。
- **编排层**：驱动工序状态机，决定"下一步指令 + 由哪个 Agent/子代理执行"，管理检查点、门禁、预算。
- **Agent 层**：主编剧执行 Agent 循环，派生子代理，通过工具注册表选取动作。
- **执行层**：具体工具的实现（读写工作区、生成章节、并发调度）、一致性规则引擎、统一事件流与审计。
- **存储层**：文件系统工作区为长期状态（契约见 06），检查点为可恢复快照。
- **模型层**：统一 `LLMProvider` 接口，屏蔽云/本地差异，含结构化输出解析与降级。

依赖方向自上而下，下不依赖上；存储层不感知业务语义，只提供"按规约读写"。

## 3. C4 容器视角（Container View）

```
┌─────────────── 用户（作者 / 运营） ───────────────┐
│                                                    │
│   [Web/CLI 前端] ------------ [ API 网关 ]          │
│                                 │                   │
└─────────────────────────────────┼───────────────────┘
                                  │
                  ┌───────────────▼──────────────────┐
                  │        Novelist 核心引擎(容器)      │──┐
                  │  编排器 · 主编剧 · 子代理 · 工具集    │  │ 事件总线(进程内消息)
                  └───────────────┬──────────────────┘──┘
                                  │ 调用
                  ┌───────────────▼───────────────┐
                  │  LLM Provider 适配器层          │──► 云 API / vLLM / Ollama
                  └───────────────┬───────────────┘
                                  │
                  ┌───────────────▼───────────────┐
                  │  小说工作区(文件/项目目录)        │──► Git 版本管理
                  │  + 检查点快照                    │
                  └────────────────────────────────┘
```

- 单进程内以**事件/异步任务**解耦编排与执行（支持并行子代理）。
- 部署形态：单机多进程可满足网文节奏；未来可拆出 worker 进程池（Backlog）。

## 4. 运行拓扑与时序（静态结构下的协作）

子系统间协作始终遵循：
```
编排器 ──派发─→ 主编剧 ──Agent循环──→ 调用工具 ──读写──→ 小说工作区
                │  ▲                            │
                │  └──派生子代理(经工具交互)─────┘
                └──产出→ 一致性门禁 → 更新状态
```

### 4.1 一次"生成下一章"的主时序

```
1  作者/调度 → 编排器：请求"生成第 N+1 章"
2  编排器：检查预算/门禁 → 推进状态机到 [正文]
3  编排器 → 主编剧：派发任务 + 指令
4  主编剧：Agent 循环
    4a 调用工具 read(outline, bible) —— 只读引用(摘要)，不搬全文
    4b 若需要 → 派生子代理「文字匠」撰写初稿到草稿文件
    4c 调用工具 write_chapter(草稿) —— 写入工作区草稿
5  主编剧 → 编排器：报告完成
6  编排器：触发「一致性审查」子工序
    规则引擎(确定性) + 审校师子代理(LLM) → 告警列表
7  若存在 block 级告警 → 进入 [修订]，回主编剧修订 → 回到 6，直到通过
8  通过 → 草稿转正 → 更新伏笔/人物/时间线 → 通知可发布
```

### 4.2 并行批量生成时序
- 编排器对"相互独立、均基于已定稿细纲"的多章进行**分批并行**派发；
- 主编剧为每章派生一个独立子代理上下文，互不共享可变状态，只在完成后把结果写回各自草稿文件并合并提交；
- 并行受 `并发上限` 与 `token 预算` 双控（NFR-1/9）。

## 5. 关键运行机制

### 5.1 Agent 循环（内核）
所有 Agent（主编剧与子代理）都运行同一套循环原语，只是"系统提示 + 权限面 + 上下文供给"不同：
```
循环 {
  observe(来自工具结果 / 系统消息)
  think(推理，可写 scratchpad)
  act = choose(调用工具 | 派生子代理 | 返回结果)
  if act==工具: 执行(经权限门禁) → 记录审计 → observe(结果)
  if act==派生: 生成子代理(isolated) → 等结果 → observe(结果摘要)
  if act==返回: break
 若达到最大步数/预算: 强制收敛(输出当前状态或明确失败)
}
```

### 5.2 子代理隔离
- 子代理拥有**独立（通常是新建）的 LLM 会话**，不继承主编剧全部上下文，只接收"任务说明 + 需要的文件引用"。
- 子代理默认只读工作区，可写入**自己草稿**的文件；不允许改设定圣经正文（除授权子代理）。
- 完成后向主编剧返回**结构化结果摘要**（产物文件路径 + 关键决策 + 下一步建议），随即销毁。
- 好处：隔离副作用、避免上下文泄漏、天然支持并行（每章一个独立子代理会话）。

### 5.3 上下文预算与压缩（ADR-005）
- 为主编剧设定 token 预算；达到阈值时触发"压缩"：把当前话题细节写入工作区草稿，将主上下文压缩为摘要 + 文件引用。
- 子代理上下文在派发时即按任务裁剪，天生轻量。

### 5.4 一致性双重门禁（ADR-009，与 02-F4）
- **规则层**（确定性、零幻觉）：校验人物/地点/力量体系引用存在、时间线单调、伏笔登记未缺失等，输出 `[object, rule, status]` 结构化记录。
- **语义层**（LLM）：审校师子代理对照设定圣经泛读章节，检文风漂移、情节逻辑、言行不符。
- 两层结果合并为带 `block/warn` 级别的审计工单，驱动 `[修订]` 或放行。

### 5.5 权限与沙箱（ADR-007，F6）
- 工具按危险度分级：`safe`（读、写草稿）/ `sensitive`（写设定、批量改写）/ `danger`（删除、覆盖、发布）。
- `danger` 与部分 `sensitive` 默认走门禁：`ask`（人工）/ `allow`（放行）/ `deny`（禁止），配置可按项目持久化。
- 所有文件读写在**项目沙箱根**内，路径穿越（`..`、绝对路径越界）被拦截。

### 5.6 检查点与恢复（F1.3，NFR-3）
- 检查点 = 项目 JSON 快照（状态机进度、各实体的指针版本）+ 已批准正文文件。
- 触发时机：每个工序完成、每次批量提交、人工干预后。
- 恢复：从最近检查点重建状态；未批准草稿在事件日志中可回溯重试。

### 5.7 失败与降级（ADR-006）
- 结构化输出校验失败 → 自动重试（有限次数）→ 仍失败则转"宽松解析（返回纯文本 + 提取）",并在审计中标记降级。
- Provider 不可用 → 编排器挂起该工序并告警，不破坏工作区已有状态。

## 6. 架构质量属性落实对照

| 质量属性 | 落实机制 |
| --- | --- |
| 一致性 | 集中式编排 + 双重门禁 + 单一事实源工作区 |
| 可扩展性 | Provider 插件化、工具注册表可增、流水线工序可配 |
| 可靠性 | 检查点、事件日志重放、失败收敛 |
| 可观测性 | 事件总线全留痕、审计日志、token 计量 |
| 安全性 | 工具分级门禁、沙箱路径拦截、敏感词过滤 |
| 可维护性 | 分层依赖、契约化接口（见 07）、本文档集 |
| 成本可控 | 预算控制、上下文压缩、批量批量节流 |

## 7. 边界与依赖
- 系统**不向 Agent 暴露真实文件系统**，只暴露工作区子集与白名单工具，降低注入与误操作风险。
- 无外部消息中间件依赖；事件总线为进程内实现，未来可替换为持久化队列（Backlog）。
