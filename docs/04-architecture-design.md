# 04 · 总体架构设计

> 承接选型结论（03），描述系统的**整体结构**：逻辑分层、C4 视图、运行拓扑、关键运行机制与时序。Agent 层细节与数据/接口细节分见 05/06/07。

## 1. 设计原则

1. **唯一中枢**：主编剧 Agent 是唯一决策中枢，子代理无全局永久记忆，只能经工具访问工作区。
2. **文件即记忆**：一切跨 Agent 的长期状态落在小说工作区，会话上下文只保留"摘要 + 引用"。
3. **工具即边界**：Agent 的唯一动作手段是调用受控工具；权限门禁、审计日志、沙箱都在工具层收口。
4. **可观测为默认**：每个 Agent 动作、每次 LLM 调用都有事件记录，可完整重放。
5. **降级不塌方**：模型能力不足（如不支持工具调用）时走退化为"纯文本 + 后解析"路径，而非中断全书。
6. **人工优先**：不可逆操作一律需门禁确认；任何节点可暂停、可编辑中间产物后再继续。

## 2. 逻辑分层（Layered View）

```
┌──────────────────────────────────────────────────────────────┐
│ 交互层  UI / CLI / API 门面        (F8, 对外集成)              │
├──────────────────────────────────────────────────────────────┤
│ 编排层  流水线状态机 · 调度 · 检查点 · 权限门禁 · 预算控制        │
├──────────────────────────────────────────────────────────────┤
│ Agent 层  主编剧 Agent(Orchestrator) · 命名子代理 · 工具注册表   │
├──────────────────────────────────────────────────────────────┤
│ 执行层  工具集(Tools) · 一致性规则引擎 · 事件总线 · 审计日志      │
├──────────────────────────────────────────────────────────────┤
│ 记忆层  Memory 子系统 · 记忆检索(RAG, 语义+关键词) · 编纂/索引      │
├──────────────────────────────────────────────────────────────┤
│ 存储层  小说工作区(文件系统) · 检查点快照 · 配置/密钥 · RAG 索引    │
├──────────────────────────────────────────────────────────────┤
│ 模型层  LLM Provider 适配器(云 API / 本地) · Embedding · 降级策略  │
└──────────────────────────────────────────────────────────────┘
```

各层职责：
- **交互层**：把用户意图（起点创意、审批决策、参数偏好）注入编排层，并把状态/进度/产物呈现给用户。
- **编排层**：驱动工序状态机，决定"下一步指令 + 由哪个 Agent/子代理执行"，管理检查点、门禁、预算。
- **Agent 层**：主编剧执行 Agent 循环，派生子代理（含**命名创作子代理**与**按需角色演员**），通过工具注册表选取动作。
- **执行层**：具体工具的实现（读写工作区、生成章节、并发调度）、一致性规则引擎、统一事件流与审计。
- **记忆层**（ADR-011）：管理"事实演进"记忆——记忆片段的沉淀（编纂）、重建检索索引（RAG）、向 Agent 提供**按语义/关键词召回历史经历与事件**的能力，与存储层的权威约束（bible）区分。
- **存储层**：文件系统工作区为长期状态（契约见 06，含 bible 与 memory 两大部分）、检查点为可恢复快照、RAG 索引落盘。
- **模型层**：统一 `LLMProvider` 接口，屏蔽云/本地差异，含结构化输出解析与降级；为 RAG 提供 Embedding 向量化。

依赖方向自上而下，下不依赖上；存储层不感知业务语义，只提供"按规约读写"。

- 单进程内以**事件/异步任务**解耦编排与执行（支持并行子代理）。
- 部署形态：单机多进程可满足网文节奏；未来可拆出 worker 进程池（Backlog）。

## 4. 运行拓扑与时序（静态结构下的协作）

子系统间协作始终遵循：
```
编排器 ──派发─→ 主编剧 ──Agent循环──→ 调用工具 ──读写──→ 小说工作区
                │  ▲                            │
                │  └──派生子代理(经工具交互)─────┘
                └──产出→ 一致性门禁 → 更新状态
```

### 4.1 一次"生成下一章"的主时序

```
1  作者/调度 → 编排器：请求"生成第 N+1 章"
2  编排器：检查预算/门禁 → 推进状态机到 [正文]
3  编排器 → 主编剧：派发任务 + 指令
4  主编剧：Agent 循环
    4a 调用工具 query_memory(essence) + read(outline, bible) —— 检索/引用，不搬全文
    4b 若需"多角同一场戏" → 派生子代理「文字匠」+ 按需「角色演员」产出试演片段(见 05§5.3)
    4c 文字匠整合演员片段 + 细纲/设定 → 撰写初稿到草稿文件
    4d 调用工具 write_draft(草稿) —— 写入工作区草稿
5  主编剧 → 编排器：报告完成
6  编排器：触发「一致性审查」子工序
    规则引擎(确定性) + 审校师子代理(LLM) → 告警列表
7  若存在 block 级告警 → 进入 [修订]，回主编剧修订 → 回到 6，直到通过
8  通过 → 草稿转正
9  编排器：触发「记忆编纂」收尾工序（ADR-013）
    编纂员提炼本章剧情/人物经历/关系/伏笔/时间变化 → 冲突校验 → 写入 memory + 重建 RAG 索引
10 通知可发布
```

> 关键：**写作前先"忆"**（query_memory 召回人物近况与相关事件，解决"AI 遗忘"），**写作中用演员演**（贴合人设），**收尾后编纂入库**（把"发生了什么"沉淀，供后续继续忆）。记忆与 bible 分离（ADR-011）。

### 4.2 并行批量生成时序
- 编排器对"相互独立、均基于已定稿细纲"的多章进行**分批并行**派发；
- 主编剧为每章派生一个独立子代理上下文，互不共享可变状态，只在完成后把结果写回各自草稿文件并合并提交；
- 并行受 `并发上限` 与 `token 预算` 双控（NFR-1/9）。

#### 并行如何"照顾靠前章节产生的剧情"（人工审查意见第 1 点）
- **依赖原则**：只有"剧情因果上互不依赖、各自依赖同一批已定稿前置"的章才适合同批并行；存在因果先后/强依赖的章，编排器**强制串行或错批**，不强制并行。
- **批次前置快照（固化记忆基线）**：一批启动前，先把已发布章节+当前 bible/memory **固化为一版"批基线"**（`batch_base`），批内所有章都基于该基线写作，保证同一批内不存在"互相追赶"。
- **批内批间同步（编纂时机澄清）**：
  - **非转向章的编纂时机**：各章通过审查后即按主时序（04§4.1 第 9 步）转正并**各自立即编纂**，新记忆当下可用，供批内其余章的检索——普通并行章之间即"同步已固化事实"，无歧义。
  - **转向章的滞后发布**：批内若某章被判定"发生了影响其他章的重大转向（角色死亡、关键伏笔回收、时间线跳变）"，该章进入 **`pending_release`（不立即转正，见 06§4.2）**，其**记忆暂缓最终沉淀**，避免在批内产生"未定稿的转向被其他章误引用"。
  - **批末统一收口**：批次内所有章收束后，由编排器**一次性核定转向章**：若与其他章无冲突 → 该章与整批一起转正，其转向记忆随整批一并编纂进 `batch_base`（下一批的基线）；若冲突 → 定位并回流受影响章（`revising`）。
  - **跨批次衔接**：批末统一沉淀后的新历史立即可供下一批 `query_memory`，实现"靠前情节自动辐射到靠后章"——这是记忆子系统（ADR-011）相对"每章独写"的核心收益；批次间通过滚动 `batch_base` 自然继承前置剧情。
- **批次一致性门禁**：批量提交前后各执行一次整批 `run_rule_check`（时间线单调性、人物状态、伏笔流转在批次内的整体校验）；批次空间内的转向章须被列入该批强制串行依赖，未转正时禁供其他章引用其未定稿内容。

### 4.3 围读会（Round-table Scene，ADR-014）
- 在重场戏排演时，可选开启**受控围读会**：主编剧（主持人）发起、多个演员 Agent 经 `join_scene → say_line（互相回应）→ leave_scene` 参与交锋；主持人调度轮次、注入场景与相关记忆、并在收敛时收场。
- 围读会**必须有结束判据**（见 05§5.3）：活跃演员全部 `leave_scene`、达到 `max_rounds`、主持人判定话题收敛/达成一致、或触发预算/超时。
- 围读会话是**隔离场景**，参与者看不到彼此的未授权记忆（防串味），谈话纪要随后并入 `character_take` 供文字匠整合正文。
- 与 ADR-001 的关系：这是主编剧主持下的**受控群聊例外**，不是无编排者的自由群聊。主持人挂起/关闭场景即结束，不失控。

## 5. 关键运行机制

### 5.1 Agent 循环（内核）
所有 Agent（主编剧与子代理）都运行同一套循环原语，只是"系统提示 + 权限面 + 上下文供给"不同：
```
循环 {
  observe(来自工具结果 / 系统消息)
  think(推理，可写 scratchpad)
  act = choose(调用工具 | 派生子代理 | 返回结果)
  if act==工具: 执行(经权限门禁) → 记录审计 → observe(结果)
  if act==派生: 生成子代理(isolated) → 等结果 → observe(结果摘要)
  if act==返回: break
 若达到最大步数/预算: 强制收敛(输出当前状态或明确失败)
}
```

### 5.2 子代理隔离
- 子代理拥有**独立（通常是新建）的 LLM 会话**，不继承主编剧全部上下文，只接收"任务说明 + 需要的文件引用"。
- 子代理默认只读工作区，可写入**自己草稿**的文件；不允许改设定圣经正文（除授权子代理）。
- 完成后向主编剧返回**结构化结果摘要**（产物文件路径 + 关键决策 + 下一步建议），随即销毁。
- 好处：隔离副作用、避免上下文泄漏、天然支持并行（每章一个独立子代理会话）。

### 5.3 上下文预算与压缩（ADR-005）
- 为主编剧设定 token 预算；达到阈值时触发"压缩"：把当前话题细节写入工作区草稿，将主上下文压缩为摘要 + 文件引用。
- 子代理上下文在派发时即按任务裁剪，天生轻量。

### 5.4 一致性双重门禁（ADR-009，与 02-F4）
- **规则层**（确定性、零幻觉）：校验人物/地点/力量体系引用存在、时间线单调、伏笔登记未缺失等，输出 `[object, rule, status]` 结构化记录。
- **语义层**（LLM）：审校师子代理对照设定圣经泛读章节，检文风漂移、情节逻辑、言行不符。
- 两层结果合并为带 `block/warn` 级别的审计工单，驱动 `[修订]` 或放行。

### 5.5 权限与沙箱（ADR-007，F6）
- 工具按危险度分级：`safe`（读、写草稿）/ `sensitive`（写设定、批量改写）/ `danger`（删除、覆盖、发布）。
- `danger` 与部分 `sensitive` 默认走门禁：`ask`（人工）/ `allow`（放行）/ `deny`（禁止），配置可按项目持久化。
- 所有文件读写在**项目沙箱根**内，路径穿越（`..`、绝对路径越界）被拦截。

### 5.6 检查点与恢复（F1.3，NFR-3）
- 检查点 = 项目 JSON 快照（状态机进度、各实体的指针版本）+ 已批准正文文件。
- 触发时机：每个工序完成、每次批量提交、人工干预后。
- 恢复：从最近检查点重建状态；未批准草稿在事件日志中可回溯重试。

### 5.7 失败与降级（ADR-006）
- 结构化输出校验失败 → 自动重试（有限次数）→ 仍失败则转"宽松解析（返回纯文本 + 提取）",并在审计中标记降级。
- Provider 不可用 → 编排器挂起该工序并告警，不破坏工作区已有状态。

### 5.8 记忆子系统（Memory + RAG，ADR-011）
- **两级记忆**：
  - **global（long-term）**：沉淀在 `memory/` 工作区的半结构记忆片段（人物经历史、剧情事件流、关系变化、伏笔流转），是"这本书发生过什么"的单一事实源（见 06§3.5）。
  - **context（working）**：当前 Agent 会话的短期上下文（目标 + 在途 + 引用），沿用 5.3 压缩机制。
- **检索**：Agent 写作/审稿前经 `query_memory` 按语义（Embedding）+ 关键词召回**与当前话题相关的历史片段**，命中结果注入该任务上下文（不是拖全文）。
- **沉淀**：每章/剧情片段收尾由编纂员（Chronicler）把演进提炼为记忆片段，经**冲突校验**后写入 memory 并重建索引（见 05§5.4、06§4.4）。
- **与 bible 的关系**：bible 是"应然"（人设定义、规则），memory 是"实然"（某角色当时做了什么、经历了什么）；两者独立但互相引用（记忆片段记录引用到的 bible 实体 id）。

### 5.9 演员试演（Character Acting，ADR-012）
- 在**章内对话框段/人物重场戏**编排时，主编剧可按需为相关角色各派生一个**演员 Agent**：上下文 = 该角色人物卡 + **其近期经历的记忆摘要** + 本场景剧本/刺激点 + 文风约束。
- 演员产出 `character_take`（试演片段：第一人称或该角色视角的对白/反应/内心），作为**素材**写回临时 take 目录；文字匠再以此 + 细纲整合成第三人称正文。
- **可控性边界**：演员是"按需素材供给者"，不是独立写手——不写正文章节、不改 bible、只能读本人物卡与自己经历、默认不可读他人未授权记忆（防串味）；一个场景的多个演员彼此隔离，各自产出后在整合阶段交汇。
- 价值：单角色对角一致性 + 多角色交锋的鲜活感，显著缓解"人设漂移"。

### 5.10 供应商审核拦截降级（ADR-015）
- 云 LLM API 厂商常设内容审核，被拦截时会**拒答/返回审核错误/输出为空**，若不处理会导致章节缺段或脱节。
- Provider 层把拦截识别为专属结果类别（`MODERATION_BLOCKED`）：命中后按顺序尝试——
  1. **改写措辞重试**（有限次数，由编写/审校 Agent 换表述）；
  2. **切换 Provider/模型**（若已配置备用）；
  3. **提请人工介入**（人工改写或裁决此内容是否必须、如何呈现）；
  4. 全部失败 → 挂起该片段、标记 `moderation_pending`，**不静默跳写**，待人工后再继续该章。
- **上游预检**：正文生成前对关键对白/敏感情节运行本地敏感词预检，提前改写，降低命中厂商审核的概率。
- 拦截事件落审计日志并计入统计，便于评估"哪些主题易触发"（NFR-5）。

## 6. 架构质量属性落实对照

| 质量属性 | 落实机制 |
| --- | --- |
| 一致性 | 集中式编排 + 双重门禁 + 单一事实源工作区 + 记忆与 bible 分离校验 + 批次基线校验 |
| **记忆保真** | 编纂独写记忆、冲突校验、RAG 可召回可回溯（ADR-011/013） |
| **人设生动** | 演员 Agent 按人设+近况试演 + 受控围读会交锋（ADR-012/014） |
| **并行剧情衔接** | 依赖原则 + 批基线快照 + 批间记忆编纂沉淀（04§4.2） |
| **内容合规** | 上游敏感词预检 + 拦截分级降级 + 人工兜底（ADR-015/5.10） |
| 可扩展性 | Provider 插件化、工具注册表可增、流水线工序可配、角色演员可配 |
| 可靠性 | 检查点、事件日志重放、失败收敛、群聊收敛判据 |
| 可观测性 | 事件总线全留痕、审计日志、token 计量（含记忆读/编/检）、拦截审计 |
| 安全性 | 工具分级门禁、沙箱路径拦截、敏感词过滤、演员数据隔离 |
| 可维护性 | 分层依赖、契约化接口（见 07）、本文档集 |
| 成本可控 | 预算控制、上下文压缩、批量节流、检索命中剪枝、围读会轮次上限 |


## 7. 边界与依赖
- 系统**不向 Agent 暴露真实文件系统**，只暴露工作区子集与白名单工具，降低注入与误操作风险。
- 无外部消息中间件依赖；事件总线为进程内实现，未来可替换为持久化队列（Backlog）。
