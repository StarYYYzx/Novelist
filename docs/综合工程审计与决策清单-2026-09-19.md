### D-2 `bible_feedback.py` 全面漂移 ⭐ 推荐：重写映射层

`BIBLE_EDITABLE`（:45-107）声明的可编辑字段与现行 schema **大面积不符**：
- edit 路径给的字段名（`appearance/personality/kind/description/owner/powers` 等）在
  items/skills/locations/settings 的 schema 里不存在，而这几份 schema 恰是
  `additionalProperties: false`——**反馈写回即违规**；
- `:457` 铸 id 形如 `char_pf_ab12cd34`，**全部不匹配**各 schema 的 `^char:`/`^set:` pattern——
  add 操作产物必违契约；
- worldstate readonly 指向不存在的顶层键 `timeline`（实为 `time`）。

该通道（`novelist feedback`）目前等于带病运行。
**推荐 A**：重写 BIBLE_EDITABLE 使其逐字段对齐 schema（含 id 生成走各分区前缀规范），
并加机械检查（feedback 声明字段 ⊆ schema properties）入 G3。
备选 B：降级为"只生成建议文本、不自动写回"（写回交给 update_blueprint/人工）。

### D-3 BIBLE_CONTRACT 覆盖缺口 ⭐ 推荐：分批纳入（先补 schema 再入契约）

六个在盘文件不受契约校验（core/bible.py:21-36）：
`bible/skills.json`（schema 根类型 object 与实然 array 矛盾，**先修 schema**）、
`bible/lines.json`（schema 已有）、`memory/relationships.json`、
`memory/relationship_ledger.json`、`bible/entity_progress.json`、`bible/review_lessons.json`
（后三者无 schema）。

**推荐**：skills 改 array 根 + 入契约；lines 直接入契约；四个无 schema 的先补最小 schema
再入。一次性纳入风险：存量项目校验失败——建议入契约时只校验**存在的文件**（现状已是
该语义则直接做）。

### D-4 `promote_draft`（sensitive/ask）vs `publish`（danger/deny）重叠 ⭐ 推荐：合并

两者都是 draft→chapters 拷贝。存在廉价通道（promote=ask）绕过 publish 的 danger 门禁，
门禁分级形同虚设。
**推荐 A**：删 `promote_draft`，统一走 `publish`（danger）。影响：agent 转正一律人工批准——
与 ADR-016/审批纪律一致。
备选 B：promote 升 danger（保留两个名字）。
注：章节链路的章末转正走的是 orchestrator 内部路径，不受影响；只有工具面重叠。

### D-5 obs 预算耗尽"只瞎不拦" ⭐ 推荐：拦

agent_runner.py:361-363：观测预算耗尽后工具**仍被执行**（写工具盲写照发），仅观测替换
占位串，模型也未被告知停手，空烧剩余轮次。
**推荐 A**：耗尽后工具调用直接返回 deny 态结果（"观测预算耗尽，请立即收敛作答"），
写工具一并拦截——预算的语义本就是防爆。
备选 B：只拦写工具、放行读工具（温和版）。

### D-6 实然错位：`entity_progress.json` / `review_lessons.json` 住在应然区 bible/

两者都是实然/产出缓存（entity.py 自述"实然缓存"），却落 bible/（应然区），无 schema。
**推荐 A**：迁 `memory/`（实然区）+ 读旧位置兼容一个版本。影响面：orchestrator/entity
两处写、若干读，迁移要处理存量项目。
备选 B：留在 bible/ 但补 schema 入契约（承认现状）。

### D-7 `produce_chapter` 并发无锁 ⭐ 推荐：加项目级章节锁

docstring 自称"严格串行，同时至多一章"（orchestrator.py:1634）但全文件无锁；
server.py:103 的 HTTP 端点可并发触发同一 (vol,ch)——快照 capture/restore 与前置清理
会互踩（双双 prepare_rewrite 后一方的 restore 把另一方的新数据抹掉）。
**推荐 A**：`(project_id, vol, ch)` 级文件锁（`workspace/.locks/ch-{vol}-{ch}.lock`，
portalocker -free 纯 os.open O_CREAT|O_EXCL 即可），CLI 与 HTTP 入口同检。
备选 B：server 端串行化队列（只挡 HTTP，不挡 CLI 并行）。

### D-8 路径硬编码散落 ⭐ 推荐：分批收口（下个大批次）
