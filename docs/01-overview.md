# 01 · 项目概述与目标

## 1. 背景

大语言模型（LLM）已具备单章节级别的连贯写作能力，但**长篇小说**（尤其连载网文，动辄数十万至数百万字）仍面临四个无法靠单次生成解决的问题：

1. **上下文超限**：全书内容远超任何模型窗口，无法"一次塞进"。
2. **全局一致性**：人物设定、实力体系、时间线、地名、伏笔必须跨章节保持自洽。
3. **创作工序复杂**：世界观 → 大纲 → 细纲 → 正文 → 审查 → 修订，是多角色、多阶段、可回流的过程。
4. **质量不可控**：纯一次性生成缺乏评审与返工机制，文风漂移、剧情崩坏难以拦截。

多 Agent 系统（Multi-Agent System, MAS）通过"多个专精智能体分工协作 + 共享记忆"，是解决上述问题的自然形态。本系统（代号 **Novelist**）即以此为出发点。

## 2. 项目目标

- **G1**：在人工设定"一句话创意 + 基础偏好"后，系统可自主产出**完整的长篇小说**（卷/章级别，可连载）。
- **G2**：全书保持**设定与剧情一致性**，伏笔可登记、可回收、可追踪。
- **G3**：支持**批量并行**生产章节（网文更新节奏），同时允许人工在任意节点介入、审批、修改。
- **G4**：底层 LLM **可插拔**，不绑定任何单一厂商或部署方式。
- **G5**：以工程化方式组织 Agent（参考 Claude Code 架构范式），保证可观测、可恢复、可评测。

## 3. 非目标（范围外，本期不做）

- 不承诺"自动出版级"文学质量——系统负责工程化地组织创作与质量门禁，艺术上限取决于底层模型。
- 不做智能体之间的自由自然语言群聊（无界网状通信），控制流始终由编排层掌控。
- 不提供分布式多机 Agent 编排（单机多进程并行即可满足网文节奏，后续可扩展）。
- 不做内容安全之外的复杂审核系统（敏感词过滤为最低要求，见需求文档）。

## 4. 核心概念与术语表

| 术语 | 定义 |
| --- | --- |
| Agent / 智能体 | 由 LLM 驱动、具备循环推理与工具调用能力的执行单元。 |
| 主编剧 Agent（Orchestrator） | 系统唯一的常驻主 Agent，负责全局统筹、派发任务、仲裁结果，等价于 Claude Code 中的主 Agent。 |
| 子代理（Subagent） | 由主编剧按需派生（spawn）的短生命周期专业 Agent，任务完成后返回结果即销毁。 |
| Agent 循环（Agent Loop） | 观察 → 思考 → 行动（调用工具）→ 再观察的迭代过程，是 Claude Code 式架构的内核。 |
| 工具（Tool） | Agent 可调用的受控函数（如 write_chapter、update_character），以 JSON Schema 描述参数。 |
| 小说工作区（Workspace） | 承载项目全部持久状态的目录结构（文件即记忆/黑板），见数据设计文档。 |
| 设定圣经（Bible） | 工作区内的世界观、人物卡、时间线、伏笔等"单一事实源"文件集合。 |
| 创作流水线（Pipeline） | 大纲 → 细纲 → 正文 → 审查 → 修订的工序状态机，允许回流。 |
| 一致性检查（Consistency Check） | 对产出章节与设定圣经进行规则 + LLM 双层校验。 |
| LLM 适配器（Provider） | 统一接口下对接不同大模型后端（云 API / 本地部署）的插件。 |
| 权限门禁（Permission Gate） | 对危险/重要操作（删除、批量改写、发布）的审批机制，仿 Claude Code 权限模型。 |
| 检查点（Checkpoint） | 项目状态快照，用于中断恢复与回滚。 |

## 5. 关键设计约束（来自需求确认）

| 约束 | 取值 | 影响 |
| --- | --- | --- |
| LLM 接入 | 可插拔适配器，同时支持云 API 与本地开源模型 | 接口层抽象、Provider 插件化（见接口设计） |
| 系统形态 | 参考 Claude Code 架构：Agent 循环 + 工具 + 按需子代理 | 内核机制设计（见 Agent 设计） |
| 目标书型 | 长连载网文 / 商业化长篇 | 流水线偏向批量产出 + 强一致性保障 |
| 语言 | 默认中文创作（英文亦可，适配器无关） | 分词/敏感词/文风校验按中文优先 |
| 平台 | Windows 优先（当前开发机），跨平台设计 | 路径处理、进程管理需跨平台 |
