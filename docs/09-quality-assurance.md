# 09 · 质量保障与评测

> 系统的一致性、记忆保真与整体质量如何验证与保障。对应 02 的非功能需求（NFR-2/3/4/7/10）。本文档由 08 拆分独立而来，并扩展了**记忆子系统**相关的质量与评测维度。

## 1. 质量目标（对应 NFR）
- 一致性规则层零失败（NFR-4 基线）。
- Provider 可插拔不受核心改动影响（NFR-2）。
- 每次变更可回归（NFR-7）。
- 结果质量可用离线评测集量化（NFR-10）。
- **记忆保真**：沉淀到记忆层的内容不丢失、不污染、可被准确检索（新增，见 §3）。

## 2. 测试策略

| 层 | 方式 | 工具 |
| --- | --- | --- |
| 单元 | Provider 抽象（用 mock/fake completion）、工具、规则引擎、状态机、记忆检索器(mock embedding) | pytest |
| 集成 | 工作区读写→工具→一致性→记忆沉淀/检索全链路 | pytest + tmp 工作区 |
| 契约 | schema 校验、事件日志 schema、记忆条目 schema | jsonschema / pydantic |
| E2E | 跑通"创意→1章"、及"20 章一致性/记忆自洽" | CI 长任务 |
| RAG | 检索命中率、排序质量、跨卷上下文回溯单元 | 专项数据集 |
| 围读会 | 结束判据触发、越权读记忆隔离、场景关闭 | 专项场景集 |
| 审核拦截 | FakeProvider 注入拒答/审核错误，验证降级链 | 专项 |
| 事件回写 | 事件落定即实时回写 memory、冲突双检、下一书写点可先忆 | 专项 |
| 沙箱安全 | 路径穿越、越界读写的负面用例 | 专项 |

### 2.1 LLM 相关测试黄金法则
- 单元测试**绝不真正调 LLM**，用 FakeProvider 注入（确定性，含"拦截/拒答"模拟）；RAG 单元测试用固定 embedding 向量。
- 真实模型调用进**集成/评测**，受 budget 控制、可标记 skip。
- 适配器测试覆盖 `capabilities` 差异导致的降级路径，以及 `MODERATION_BLOCKED` 识别与处理链。

## 3. 评测集与评分（NFR-10）

评测集 = 一组"已知正确/应改"的样例项目（含设定圣经 + 大纲 + 若干章 + **需要回忆的历史情节**），供自动跑分。

| 维度 | 说明 | 指标 |
| --- | --- | --- |
| 设定一致性 | 人物/地点/力量/时间线不矛盾 | 引用完整率、矛盾数 |
| **记忆保真** | 记忆沉淀内容与正文事实一致、无幻觉新增 | 沉淀准确率（抽查比对） |
| **记忆检索** | 按"人物近况/事件因果/关系变化"提问能召回正确历史片段 | 命中率@k、排序 NDCG |
| **人设保持** | 演员产出的对白/反应符合人物卡 + 近期经历 | 抽样人工评分 |
| **围读收敛** | 围读会能否在判据内收敛、是否出现失控绕圈 | 结束判据命中率、越权/失控发生数 |
| **审核恢复** | 拦截后能否经改写/切换/人工路径恢复不缺章 | 恢复成功率、拦截→恢复耗时时延 |
| 文风保持 | 叙述与角色语气符合 style.json；整合后首尾一致 | 抽样人工 + 易检信号 |
| 情节逻辑 | 事件因果、伏笔回收合理 | 抽样人工评分 |
| 结构化输出 | 契约解析成功率 | json parse/validate 通过率 |
| 门禁正确 | 危险操作均可被正确拦截/放行 | 用例通过率 |
| 成本效率 | 每章 token 用量（含记忆检索与编纂额外开销） | 实测统计 |

评分在执行 `novelist eval <evalset>` 后输出报告（落 `reports/stats/`）。记忆相关维度是长期连载特有的回归项，需随评测集章节数增长持续复测。

## 4. 一致性保障的持续质检（上线后）
- 每章转正前置 `run_rule_check`（block 级阻断）。
- `run_semantic_check` 结果进入审查工单驱动修订。
- **记忆沉淀质检**：每章编纂片段后校验"新增记忆是否与既有 bible/memory 冲突"（规则 + 语义双层），冲突者回退或提示人工（见 06§4.4 编纂工序、05§5.4）。
- **事件回写质检**：每个事件落定即校验新增记忆是否与既有 bible/memory 冲突（规则 + 语义双层），冲突者回退或提示人工（见 06§4.4、05§5.4）；确认事件不会积压至章末（NFR-13/14）。
- **审核拦截监控**：统计 `MODERATION_BLOCKED` 事件数与恢复成功率，识别易触发主题并纳入上游预检策略（ADR-015）。
- 统计化监控：设定实体新增/矛盾趋势、伏笔逾期数量、**记忆索引覆盖率**、围读会收敛率，供人工关注。

## 5. 人工评价与审计
- 阶段性抽样人工评审（release 门禁），含对**演员试演片段 → 整合正文**质量的抽查。
- 基于事件日志的完整审计重放可用于定位质量问题根因（记忆读、编、检索均落审计）。

## 6. 验收回归对照
验收标准 A1–A10（02§5）分别映射到 M2/M3/M4 的 E2E：
- A1/A2 → M2 一致性封闭；A3 → M4 多 Provider E2E；A4 → 检查点 kill-test；A5 → 门禁用例；A6 → 导出+过滤测试。
- **A7（记忆自洽）**：编写第 N+1 章时，能通过记忆检索召回第 1 章埋下的待回收伏笔与人物近况，且无内容矛盾 → M3 记忆闭环。
- **A8（人设保真）**：演员试演片段与人物卡/近况摘要无明显不符（抽样），多角对手戏整合连贯 → M3。
- **A9（事件实时回写）**：某事件落定后，对应人物经历/剧情事件/关系/伏笔/时间记录立即更新并可从 `query_memory` 命中，无需等到章末 → M3。
- **A10（审核拦截）**：注入 FakeProvider 拒答后经改写/切换/人工路径恢复，无缺章 → M3/M4。
