## 2. 整改方案（五个批次，按"先止血后治病"排序）

### 批次 UX-1：审批减负（对齐编码 agent 的 permission 模式）——半天

编码 agent 对照：Claude Code 的 `allow always` / `--dangerously-skip-permissions`；CodeBuddy 的
「始终允许」。核心语义 = **按域授权一次，后续免问**。

| 改动 | 落点 |
|---|---|
| `forge approve all [--remember]`：批量批准全部 pending | `cli.py forge_approve` + `review.py` 加 `resolve_all_pending()` |
| shell `/approve all`、`/approve <模块> --remember`（把已有能力暴露进 shell） | `shell.py` HELP_TEXT + 命令分发 |
| **新增 `/approve-all <模块>`**：= approve + remember（永久关该模块开关）；**`/approve-all all`**：全部模块开关永久关闭（写入 review.json switches 全 false） | `review.py.set_switch` 复用；switches 全关后闸门在 `mark_pending` 前置短路（开关全关 → build 不停） |
| `forge switches` 增强：`switches all off/on` 批量开关 | `cli.py forge_switches` |
| 守卫：approve-all all 打印**一行醒目确认**（"后续构建不再人工审核任何模块"），并记入 history（`decision="approve-all"`）——放权要留痕，不要静默 | `review.py` |
| 测试：批量批准/all 语义/开关短路/留痕 4 例 | `tests/test_forge_review_gate*.py` 就近扩展 |

**边界**：这只动 **forge 审核闸门**（内容质量的人工签收）。工具级 PermissionGate（写文件/发布/
删除的 ask/deny）**不动**——那是安全边界，不是审核体验。两个"approve"语义不同，文档里写清。

### 批次 UX-2：构建可见性（思考提示）——半天
