## 二、推荐选题与贡献声明

**题目（工作名）**：*Dual-Track Context: Planned-Actual State Arbitration with Assembly-Time Budgeting for Long-Horizon Generation Agents*

**一句话**：长时程生成 agent 需要同时持有"计划态"（应然）与"实况态"（实然）两条一等公民状态轨，并以确定性仲裁 + 装配时分层预算替代事后压缩与语义检索，才能在超长任务上守住硬约束。

三条贡献：

1. **双轨状态形式化**：planned（蓝图/细纲，可被修订）与 actual（事件回写/硬状态，只增不删）分离存储；注入时以确定性声明仲裁（"冲突以实然为准"），冲突入账本可审计。区别于 ConPAct（双 agent 断言比对、无持久状态文件）与 NarraWorld（图检索、无文件级双轨）。
2. **装配时分层预算**：钉死层（载重约束永不压缩）+ 可淘汰层（按 EVICT_PRIORITY 优先级淘汰、淘汰留痕）。正面回应 Lost in Compaction（2608.x，压缩静默丢弃侧约束）与 Governance Decay（2606.x）的失败模式——**约束在装配时就被钉住，而不是压缩后祈祷它活下来**。
3. **可测量评测协议**：把"一致性"拆成可计算的约束满足率（见 §4），并首次把**缓存命中率/成本**作为上下文机制的一等指标（DeepSeek 前缀缓存命中价差 50 倍，机制设计直接改变成本曲线）。

## 四、实验设计

### 4.1 场景与基准
- **主场景**：长篇叙事生成 10K → 100K 词（沿用 NstAgent 公开的长度扩展评测协议与 benchmark，保证可比性；其 code/data 已开源）。
- **第二场景（冲 A 必做）**：把双轨+预算机制移植到一个非叙事长时程任务，候选：① 交互式行程规划（约束随执行累积）；② 仓库演进式代码任务（计划 issue 清单 vs 实际改动）。证明机制非叙事特化。

### 4.2 基线（7 条）
1. 直接长上下文单提示（upper bound 参考）
2. 层级大纲式（Re3/DOC 形态）
3. RollSum（NstAgent 的滚动摘要基线）
4. **NstAgent 本体**（开源，必打）
5. Letta/MemGPT 自管记忆
6. 朴素 top-k RAG 记忆（Mem0 形态）
7. 事后压缩（ReSum 式周期折叠）——钉死层消融的直接对照组

### 4.3 指标
- **硬约束满足率（本文核心卖点，确定性可测，不依赖 judge）**：
  - 属性冲突率：境界倒退 / 死者复活 / 位置瞬移（worldstate 可机器判定）
  - 别名共指错误率（"叶岚/叶师弟"被当两人）
  - 禁用词/现代词违规率（词表可测）
  - **伏笔回收率**：planted 数 vs payoff 窗口内回收数（T3 机制作为指标落地）
  - 实体引入配额遵守率
- **质量**：LLM-as-judge 多维 rubric（judge 与生成模型不同家族）+ 人评（≥5 人，成对比较，报告 Kappa）
- **成本（一等指标）**：总 token、**缓存命中率**、$/千词、墙钟时间
- **扩展曲线**：各指标 vs 长度（10K/25K/50K/100K），核心 claim = 约束满足率**不随长度衰减**

### 4.4 消融（4 组，对应贡献逐条拆）
- A1 去仲裁：双轨合并为单轨快照（≈ NstAgent 形态）
- A2 去钉死层：允许载重约束被淘汰/压缩（≈ 事后压缩形态）
- A3 去确定性读：实然状态改走 top-k 语义检索（≈ Mem0 形态）
- A4 随机淘汰 vs EVICT_PRIORITY

### 4.5 统计与可信度
- 每配置 ≥3 seeds（温度>0），报均值±方差 + 配对检验
- judge 校验：人工抽检 200 样本对齐 judge 偏差
- 全部走真实 API（`@pytest.mark.slow` 形态），附 raw-calls 式全量调用日志供审稿人复核

## 六、风险与时间窗

1. **赛道正热**：NstAgent 与 NarraWorld 都是 2026-09 挂出，竞争窗口 6 个月内必须占位（arXiv preprint 先行）。
2. **API 预算**：100K 词 × 7 基线 × 3 seeds 估算 2–4 千万 token 量级，需先做单配置小样估成本（现系统 `NOVELIST_HTTP_TIMEOUT_S` + 官方端点已具备条件）。
3. **差异化滑坡风险**：若评审认为双轨 ≈ "多存一份文件"，必须在 related work 里用 ConPAct 的 85% 失败率数据 + 我们 A1 消融（预期：单轨形态的属性冲突率显著上升）把差异做实。
4. **可比性依赖**：主基线是别人家的 benchmark，若其评测协议变更需 fork 固化版本。
