## 1. 问题与动机（为什么要做）

lingyu5 真机实证：宗门暗线在 5 章 7654 字中仅 3 次名词提及、**零处暗线场景**（拍板④要求每章一段）。
与"人设卡没送到眼前"同病——信息在账上，但生成时看不见。三个机理断点：

1. **threads 语义=伏笔**：状态机 `planted→pending_return→returned`，核心字段 target_vol（回收卷）。
   系统只问"这条线何时收"，从不问"这章在不在场"。
2. **细纲与生成交界断线**：章纲让模型填 `threads_involved`（forge/nodes.py 章纲 prompt），
   core/ 全目录零消费；context.py 读 plot_threads 也只在事件级 RAG 命中时注入。
   且 `related:thread` 在 prompt_budget.EVICT_PRIORITY=14（比教训、势力还先丢）。
3. **人物有调度层，线索没有**：ADR-020 给人物建了 director/调度表；"前面主角一段、后面宗门一段"
   的章内结构无机制规划。

可复用底子（不必从零造）：
- chronicler.py 已有事件↔线关联+状态流转（关键词命中→active、收尾→paid_off）；
  `Extraction` 是具名容器，加"线索行"不改调用方签名。
- entity.py `dormant_since(ch, min_gap=5)` 冷却查询模式。
- broadcast/prompt_budget 的**钉死层**（priority -1，first_seen/banned_names）注入模式。
- phase.py 开篇/收尾期判定（PhasePolicy）+ payoff_checklist。

## 2. 数据模型：bible/lines.json

单一文件（ADR-016 文件=事实源）；字段按 ADR-011 分应然/实然两组。

```json
{
  "id": "ln:qingyunzong",
  "desc": "青云宗察觉青山镇灵气异动，渐次派员查探",
  "kind": "subplot",            // 应然：main主线 / subplot支线 / hidden暗线(即现行伏笔)
  "carrier": "faction",         // 应然可选：object物 / goal行动 / character人 / emotion情感 / faction组织 / theme主题
  "scope": "volume",            // 应然：book跨卷 / volume卷内
  "members": ["char:chen_feng", "faction:qingyunzong"],
  "status": "active",           // 实然：dormant→active⇄suspended→closed；另有 pending(提名待审)
  "opened": {"vol": 1, "ch": 2},
  "last_seen": {"vol": 1, "ch": 3},
  "progress": ["1-2 宗门收到密报", "1-3 陈锋探院察觉异样但无实据"],   // 实然，只追加
  "target": {"vol": 2, "note": "执法堂正式介入"},   // 应然远期落点，main 必填
  "yield": null,                // 闭合时登记：该线留给主线的收获（情报/能力/盟友/代价）
  "closed": null                // 实然：{vol, ch, reason}；留档供一致性检查拦"死线复活"
}
```

**入账判据（三问，写入 Chronicler 提名 prompt 与人工转正清单）**：
多次出场横跨章节？（贯穿）多段剧情因它相连？（串联）角色为它做抉择、剧情被它影响？（价值）。
判据的本质是"能不能串起剧情"，**不是"自身是否变化"**（玉佩不变可是核心物线；天气一直在变只是背景）。

## 3. 生命周期与闸门（一硬多警）

```
蓝图book节点      卷纲节点           章纲节点(人审)          正文+Chronicler         卷末盘点
骨架登记★硬校验   开线计划+预算★警   lines_present★人审落定  实时回写(开/推/闭/交织)  到期审计+篇幅比
dormant ──────────────────────────→ active ──advance/flicker──→ progress 追加        yield 校验
                                      │  ↑ suspend(显式+resume_hint)                     未闭合→下卷强制项
                                      └── close（事件闭合为主；计划外=candidate→人工）──→ closed 留档
```

- **开线三级**：蓝图骨架登记（dormant，仅账本一行；**主线唯一=硬校验，main 的 target 必填**）→
  卷纲细化本卷开线计划（**活跃支线≤3=告警级预算**，超出提示挂起最冷线）→
  章纲 `lines_present` 填动作并过人审 = `opened` 落定，dormant→active。
- **章级动作**：`open / advance / suspend / flicker / close`。flicker 为主线休眠章的合法形态
  （纯支线章，主线只在末尾一两段露苗头）——"每章必须推进主线"的隐含强制由此解除。
- **分档冷却**（告警级，对齐 dormant_since 模式）：main 2-3 章内必须 flicker/advance；
  subplot 5 章；hidden 可跨卷（伏笔型静默合法）。超阈值→章纲冷却告警置顶，强制"露面或显式挂起"二选一。
- **收尾期禁开线**（告警级）：PhasePolicy TAIL 期章纲出现 open 动作→告警；开篇期 hidden 只许埋不许揭开→告警。
- **闭合**：主路径=事件闭合。Chronicler 抽"线索行"（开/推/闭/交织/反转），确定性校验
  （线在账本、事件语义命中 members/desc 关键词）：与 target 计划吻合→自动闭合留痕；
  计划外→closing_candidate，章末汇总人工确认。**closed 不删**，一致性检查拦"已闭合线被当活线再提"。
- **卷末到期审计**（非强检）：target_vol 已到/将到但未见闭合事件→告警+写进下卷卷纲强制处理项；
  volume 线闭合时 yield 非空校验；支线/主线 progress 占比启发式告警（防支线抢主线，纯统计零 LLM 成本）。
- **失败降级**（ADR-021 纪律）：线索识别/校验任何异常→降级为现状行为，绝不阻断生成；每章变更落盘留痕可审。

## 4. 注入：一份账本，四级视图

| 环节 | 注入内容 | 粒度/预算 |
|---|---|---|
| 卷纲节点 | dormant 骨架全集 + 上卷延续 active 线 + **前卷闭合线 yield 收获**（支线收获回流主线的落点） | 干线清单，一次 |
| 章纲节点（唯一决策层） | active 全量视图（单行卡）+ 冷却告警置顶 + closed 禁复活负清单 + 首开线附 desc 全文 | ~300-400 字块 |
| 事件生成（唯一执行层） | **只给本场命中的线**（事件 line_ids 命中）+ 线内成员状态 + 交织标注；**钉死层（priority -1）** | ~80 字/线，≤3 线/事件 |
| 润色 global_context | 禁令一两行：暗线不点破、闭合线不得当活线写 | <50 字 |

**单行卡格式**（不给 desc 全文、不给全量 progress——账本是给系统读的，模型只要"当前状态+本章目标"）：

```
ln:qingyunzong 支线·active | 上次1-3(距2章) | 1-2密报→1-3探院无实据 | 本章:推进→执法堂立项
```

- 排序：主线恒在 → 冷却告警线置顶 → 其余按 last_seen 升序；超预算截断附"挂起建议"（丢失逼成显式决策）。
- 交织只标在事件层（"本事件=X线×Y线交织点"）；章纲层只说"本章有交织"。
- 反模式排除：不做 RAG 命中才注入（未命中=沉默）；不整本塞 system prompt。

## 5. 分阶段工作规划（两批）

### 批 1：完整闭环（阶段 1-4）

**阶段 1 数据层**（纯数据，无 LLM 行为变化）
- `schemas/bible/lines.schema.json`（或并入 bible schema）；`core/lines.py`：
  load/save（原子写）/视图生成（四级）/冷却计算/三问提名 pending 区/provenance。
- 一致性校验函数：死线复活、closed 不可变、main 唯一。
- 验收：单测 ~10 条；现有项目加载不受影响（缺文件=空账本降级）。

**阶段 2 规划侧落线**
- book 节点（forge/nodes.py）：threads 骨架扩展登记 kind/carrier/target + 主线唯一硬校验。
- 卷纲节点：summary 升**五元组**（目标/阻碍/达成或失败/结果含代价/衔接下节）——outcome 允许受挫，
  key_beats 采样代价事件（对治老问题 C1）；注入 dormant 全集+前卷 yield；产出本卷开线计划+活跃预算。
- 章纲节点：新增 `lines_present` 生成（动作 open/advance/suspend/flicker/close + 一句话目标）+
  确定性校验（收尾期禁 open 告警、开篇期 hidden 禁揭开告警、冷却告警、预算告警）；
  `threads_involved` 消费打通（细纲→事件）。
- schema 更新：volumes 五元组字段、chapters.lines_present；`chapter_range` 注释降级为"预期区间"。
- 验收：单测（fake provider 脚本序）；蓝图闸门人审点不变。

**阶段 3 生成侧注入**
- prompt_budget.py：新增 `lines` 钉死层（-1），从可淘汰层摘除 related:thread。
- orchestrator 事件 prompt：命中线卡+成员状态+交织标注；润色 global_context 禁令行（polish.py）。
- 验收：单测 prompt 组装快照；事件 prompt 不再依赖 RAG 命中。

**阶段 4 回写闭环**
- chronicler.py：Extraction 加"线索行"（`线索：ln:xxx | 开|推|闭|交织|反转 | 一句话`）+
  确定性校验 + 实时回写 lines.json（开/推/闭/progress 追加/last_seen）+ 计划外闭合 candidate 章末汇总
  + 提名 pending 落账。
- 验收：单测（关键词命中/校验失败降级/candidate 不即闭）；全量回归绿。

### 批 2：检查点、审计与真机（阶段 5-6）

**阶段 5 检查点与审计**
- 卷中检查点：本卷 ~50% 章落定后自查主线节进度（阶段结果是否可见），报告 + 未落地项写进剩余章纲强制项。
- 卷末到期审计 + 篇幅比告警 + yield 校验落 reports；一致性引擎接死线复活拦截。
- revise 通道转正：生产期细纲修订过 gate + 账本联动（把"人工改细纲"从地下行为变成正式流程）。
- 验收：单测； lingyu5 旧项目只读跑审计报告验证（不回写）。

**阶段 6 真机验收**
- 用户新出一句话需求（多线密集题材）→ 四问细化 → 全流程 5 章。
- 验收清单：
  - [ ] 主线每章可见（advance 或 flicker），无无声失联；
  - [ ] ≥2 条支线按预算在场，至少 1 章支线占大头（flicker 章）；
  - [ ] ≥1 条暗线埋设不揭开；
  - [ ] ≥1 次多线交织（一事件带 2 line_ids）；
  - [ ] 冷却告警至少触发 1 次且被章纲显式处置（露面或挂起）；
  - [ ] 卷末/章末线索账本 diff 与正文一致（无凭空开线/死线复活）；
  - [ ] 事件 prompt 含命中线卡（钉死层，非 RAG）。
