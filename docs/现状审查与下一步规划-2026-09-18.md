## 2. 已核实缺陷（P0，会致真实故障）

### P0-1 正文落盘非原子 —— 中断即留半章 `✓核实`

- `storage/workspace.py:177-180` `write_text()` 直接 `open(path,"w")` 覆写；同一文件 `write_json()`（:161-167）用了 tmp+rename。
- 影响面：全部正文/草稿/细纲走这条通道（`core/orchestrator.py:2400/2420/2500/2520/2632`、`tools/writing.py:30`）。写章中途 Ctrl-C / 进程被杀 / 磁盘满 → 目标 `.md` 被截断成半成品，且**旧内容已丢失**（A DR-016 的"文件即事实源"在此处不成立）。
- `tools/writing.py:3` docstring 还写着"原子写" —— 文档与实现不符。
- 改法：`write_text` 改为同名 tmp + `os.replace`；`writing.py:3` 措辞保留（改后即名副其实）。

### P0-2 `write_file` 定级 `safe`，可绕过 danger 门禁写任意文件 `✓核实`

- `tools/filesys.py:91` `Tool("write_file", ..., "safe", _write, ...)`；`safe` 在 `core/tools.py:318` 直接 `return APPROVAL_ALLOW`（无审批、无审计）。
- 路径基准是**沙箱根**而非项目目录：`filesys.py:30` `ws._abs(rel)` → `workspace.py:59` 相对 `root` 解析。
- 后果：Agent 可直接写 `<root>/<其它项目>/project.json`、`.../chapters/1-1.md`，**绕开 `publish`（danger）/ `promote_draft`（sensitive）的审批链**，也能跨项目串改。这是 AG-8~AG-10 收紧门禁后留下的旁路口子。

### P0-3 `delete_file` 白名单校验与实际解析基准不一致 `✓核实`

- `tools/governance.py:74` 按 `rel_in_proj`（剥掉项目名）校验白名单 `drafts/`、`workspace/`；
  `:81` 却用**原始 `raw`** 相对沙箱根解析 `p = ws._abs(raw)`。
- 两个后果：① 工具描述（:107）写"仅 `drafts/`、`workspace/` 下"，模型照此传 `drafts/1-1.md` → 解析到 `<root>/drafts/1-1.md`（项目外）→ 永远 `NOT_FOUND`；② 传 `<其它项目>/drafts/x.md` 时白名单照样通过 → **可删别的项目文件**。
- 改法：统一按"相对项目目录"解析（或统一按"相对沙箱根"，同时把白名单改成 `*/drafts/*`），并让校验与解析用**同一个** `p`。

### P0-4 HTTP 服务永远读不到 config.toml `✓核实`

- `server.py:29` `cfg = load_config()` 无参 → `config.py:101-104` `if not path: return Config()`。
- 于是 `server.py:30` `cfg.storage.workspace_root or "."` 恒为 `"."`，`[storage]`、`[security]`、`[budget]` 对服务端**全部无效**；CLI 侧却读得到（`cli.py:47` 传了 path）。同一份配置两条路径行为不同。

### P0-5 `project.json` 读取失败时被洗成空壳 `✓核实`

- `tools/governance.py:33-38`：`except Exception: current = {}` → `current.update(patch)` → `ck.save(...)`。
- AG-4 修好了正常路径（读-改-写），但**失败路径把老 bug 原样放回**：一旦 project.json 损坏或读取抛错（编码/权限/IO），`publish`（:58，patch 仅 `pipeline_state`）与 `checkpoint`（:99）会把 `event_seq / phase / next / title` 全部抹掉。
- 改法：区分"文件不存在"（可空档起步）与"存在但读失败"（必须 `fail(INTERNAL)`，不得覆写）。

### P0-6 Forge 失败路径仍 `bp.save()`（事务未覆盖全部写入点）`✓核实`

- `forge/engine.py:513`：节点 `res is None`（失败）后无条件 `bp.save(ws, project_id)`。事务（`nodes.py:1898` `blueprint_txn`）保证内容已回滚，所以**不会写脏数据**，但会**在失败路径上额外落盘一次**；同类裸 `save()` 全库 32 处（`engine.py` 17、`ask.py` 4、`ingest.py` 3、`shell.py` 4、`conflicts.py` 1、`seed.py` 1）。
- 风险：未来任何"先改后校验"的新 `_apply_*` 若绕过 `blueprint_txn`，09-16 事故重演。建议加**机械检查**（§7 批次 A-6）。
