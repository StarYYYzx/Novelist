## 4. 待拍板（2 项）

### 拍板 1：模型给出**第二条主线**时怎么处置？

现状 = 硬校验拒绝 → 重试 1 次 → 仍失败则该**整个 book 节点**产出作废（世界观/人物/伏笔/文风
一起丢，回退到 seed 骨架）。用户在本次事故里就撞上了：因为"因果"被写成第二条主线，
**45s + 63s 的两次生成全部白费**。

| 选项 | 行为 | 代价 |
| --- | --- | --- |
| ⓐ 保持拒绝（现状） | 语义最严格，模型错一次就整节点重来 | 一次措辞重复 = 整轮 book 产出作废 |
| ⓑ **自动降级 + 留痕（推荐）** | 保留第一条 main（优先与骨架同 id 的那条），其余 main **降为 `subplot`**，warn 写明「`ln:main_yinguo` 已降为支线；确需它当主线请改 kind 后重跑」 | 模型确实想表达两条主线时结构被自动改动（但有留痕、可手改） |
| ⓒ 自动合并 | 把第二条并入第一条（desc 拼接、target 取更远者、members 并集） | 合并规则复杂，可能把两条真不同的主线揉成一条且不易察觉 |

### 拍板 2：**根节点（L0 book）失败**时要不要直接中止本轮构建？

现状（已修）是"节点级回滚 + 构建继续跑其余节点"（docs/10 的"父层兜底"）。但 `book` 是整棵树的根：
它失败意味着后续 volume/chapter 都长在**旧骨架**上，而同时期 L1 节点（worldview/style）却用了新内容
——本次实测就是"新世界观 + 旧骨架"的混血产物（45.1s / 63.4s 两次调用的产出与旧骨架混用）。

| 选项 | 行为 | 代价 |
| --- | --- | --- |
| ⓐ 继续跑（现状） | 省预算、能部分推进 | 树可能"半新半旧"，自相矛盾且不易察觉 |
| ⓑ **L0 失败即中止（推荐）** | `book` 失败 → 中止本轮并明确提示（L1 及以下仍按"回滚 + 继续"） | 少一次"能部分推进"的机会；但避免烧钱产混血产物 |
| ⓒ 失败后自动重跑整棵 | 提高成功率 | 预算翻倍，且本仓"可接受多调用换质量"并不等于无限重试 |
