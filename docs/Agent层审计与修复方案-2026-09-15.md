# Agent 层审计与修复方案（2026-09-15）

> **范围**：Agent 循环与工具调用链路 —— `core/agent_runner.py`、`core/tools.py`、`core/llm.py`（消息/请求契约）、
> `core/session.py`（预算）、`core/approval.py`、`tools/*.py`、`providers/openai.py`，以及两个子代理
> （`core/chronicler_agent.py`、`consistency/reviewer_agent.py`）与 orchestrator 的工具模式入口。
> **对照规范**：docs/04 §5.1–§5.10（Agent 循环原语/子代理隔离/上下文预算/权限沙箱/失败降级/审核拦截）、
> docs/05 §4（工具表与分级）、docs/07 §2.2/§3（请求契约与门禁），以及 Agent 工程通行规范
> （原生 tool 消息协议、能力门控、观测截断、预算闭环、失败可自纠、门禁 fail-closed）。
> **方法**：逐行审计 + 5 组离线可执行复现（下列每条均给复现命令与实测输出）+ 真机审计反查。
> **结论**：链路三件套（`LLMRequest.tools` 字段 / openai 往返解析 / ToolRegistry 门禁）**都在**，
> 但**工具定义从未下发给模型**，且"默认生成模式"正是这条不可用的路径 —— 这是本批最重的问题。

---

## 0. 一句话结论

| 维度 | 现状 |
| --- | --- |
| 直接对话触发 FC | 不能（console 无非 `/` 入口；shell 自由语是单次 JSON 文本分派，属设计使然） |
| `chapter --loop`（设计上的 FC 路径） | **真机必然退化**：工具定义从未下发 → 模型永不返回 `tool_calls` → 循环退化为"单轮直出" |
| 默认生成模式 | **就是 `mode="tool"`**（`cli.py:369` → `orchestrator.py:1760`），而文档写的是"默认 direct" |
| 后果 | 草稿不落盘 + `ok=True` + `chapter_path` 指向不存在的文件 + 事件流被写入一条空章事件 |
| 真机佐证 | 72 份真机生成审计：`direct` 67 次、`tool` 5 次；5 次 tool 全部是 2026-09-06 那次"缺陷 DA"暴露现场 |

## 2. 复现记录（全部离线、不碰真机、不调真实 API）

### 复现 1 · 默认模式不落盘（`prefer_direct` 不传 · 桩 provider 只回文本）

```
res.ok           = True
res.mode         = tool
草稿文件存在      = False
res.chapter_path = ...\<tmp>\p\drafts\chapters\1-1.md   ← 指向不存在的文件
req.tools 实际下发 = None                                ← 工具定义从未下发
LLM 调用次数      = 1
```

### 复现 2 · `checkpoint` 工具清空 project.json

```
调用前 = {'id': 'p', 'title': '长夜', 'pipeline_state': '写作', 'event_seq': 57, 'phase': 'mid', 'next': {...}}
工具结果 = ok {'ok': True}
调用后 = {'id': 'p', '_manual': True}
→ 丢失字段 = ['event_seq', 'next', 'phase', 'pipeline_state', 'title']
```

### 复现 3b · 门禁未知取值 fail-open

```
gate.check → alow            （策略写成 "alow"，拼错的 allow）
invoke     → ok HANDLER-EXECUTED    ← sensitive 工具被执行
```

### 复现 5 · 写类工具把失败包成 ok

```
write_draft(vol="not-an-int") → ok OK {'error': "invalid literal for int() with base 10: 'not-an-int'"}
```

### 复现 6 · 工具异常不带任何信息

```
除以零   → error INTERNAL data = None
缺参数   → error INTERNAL data = None
未知工具 → error NOT_FOUND {'name': 'no_such_tool'}
```

### 复现 7 · 策略文件缺 supervised 段 → 所有工具调用崩

```
PermissionGate({"strict": {"danger": "deny"}}).check(profile="strict") → KeyError 'supervised'
（请求的 profile 其实存在）
```

### 复现 8 · 审核拦截 / 空内容静默成功（并污染事件流）

```
审核拦截(blocked) → ok=True | 草稿存在=False | len(result)=0 | events=1 | soft_failures=[]
空内容(empty)     → ok=True | 草稿存在=False | len(result)=0 | events=1 | soft_failures=[]
写入了事件：ev:<pid>:1:1:1  type=chapter  summary="完成第 1 卷第 1 章"  participants=[]
（event_seq 仍为 0 —— 重跑该章会撞同一个 id）
```

### 批 A · 止血：不再"静默成功"（**不需要拍板**，改动小、收益最大）

| 项 | 修法 | 落点 |
| --- | --- | --- |

## 4. 建议顺序与不改变行为的边界

1. **批 A 先做**（无拍板项，直接堵住"静默成功"与数据丢失）。
2. **批 B 需要先拍默认模式**；接线后必须真机 3–5 章验收（`--loop` + `--direct` 各跑一遍对比），
   并用 `raw-calls/*.jsonl` 实证 `tool_calls` 往返真的发生。
3. **批 C 随时可插**（与 A/B 无耦合）。
4. **批 D 最后**（AG-11/12/13 三项拍板后再动；AG-18 文档可与批 B 同批）。

**不改变行为的承诺**：批 A/C 不改任何 prompt 与产物形态；批 B 在"默认模式"拍板为 ⓑ 时，
默认产物回到真机一直在用的 direct 形态（**等价于现状实际行为**，只是把文档写对）。
