## 1. 代码级缺陷

### 1.1 🔴 D1（P0）· embedding 惰性降级失效 —— 记忆层静默为空 / CLI 崩溃

**现象**：`make_embedding("auto")`（`config.provider.embedding` 的默认值）返回 `LocalEmbedding`，
但**构造期探针只查 `import fastembed`，不加载模型**；首次 `embed()` 才真正下载/加载。

**复现**（本机实测）：

```
$ python -c "from novelist.core.embedding import make_embedding; e=make_embedding('auto'); print(type(e).__name__); e.embed(['测试'])"
LocalEmbedding
ProviderError: fastembed load failed: [WinError 10060] 连接尝试失败
```

`fastembed 0.8.0` 已安装、`%TEMP%\fastembed_cache` 为**空**（P-FE1 现实验证）、HF 直连超时。
`_ensure_backend()`（`embedding.py:186-206`）把加载失败包成 `ProviderError` 抛出，
**没有任何一层把它转成 `KeywordEmbedding`** —— `make_embedding` 的降级链只在构造期生效。

**后果分两路（都已在测试里现形）**：

| 路径 | 表现 | 证据 |
|---|---|---|
| `commit_event` → `MemoryWriter.append_plot_event` → `MemoryIndex.add` → `embedding.embed()` | 抛 `ProviderError` → 被 `orchestrator.py:2581` 静默吞 → **记忆索引 0 条、命令 exit 0、草稿正常落盘** | `pytest tests/test_m3_memory.py::test_writeback_then_recall_closed_loop` 实测：`res.exit_code == 0` 通过，断言 `完成第 1 卷第 1 章 in idx.fragments` 失败 |
| CLI 前置 `_recall_lines` → `MemoryIndex.rebuild`（非空记忆时） | 异常上抛 → CLI 崩溃 exit 1 | `tests/test_m3_full_pipeline.py::test_chapter_full_pipeline` |

**为什么是 P0**：它同时打穿 `F9.4`（必须可降级）、`A9/NFR-13`（事件实时回写）、`ADR-011`
（记忆=实然事实源）。而且**失败模式是"看起来成功"**——用户拿到一章成稿，记忆层却是空的，
再写下一章时"先忆"召回不到任何东西，一致性断链。这是本系统最危险的失败形态。

**修法**（两处，缺一不可）：
1. `LocalEmbedding` 加**运行期降级**：首次 `embed()` 失败 → 置 `self._degraded=True` 并
   委托内部 `KeywordEmbedding`（同时把 `kind` 暴露为 `keyword-hash`，让检索层走精确 token 打分）；
   或让 `MemoryIndex.add/rebuild` 在 embedding 抛错时跳过向量、保留文本（检索自动降级）。
2. 缓存目录从 `%TEMP%` 挪到持久位（`NOVELIST_EMBED_CACHE` 或工作区 `.cache/`），并给一次
   带退避的重试——两坑一起收（P-FE1 + P-FE2）。

### 1.3 🔴 D3（P0）· `prose_tail` 语义塌缩 —— "1200 字滑动窗口"实际只注入最后一个段落

**现象**：`prompt_budget.prose_tail(text, window_chars)` 的文档说"取末尾约 `window_chars`
字，段落边界对齐"，实现却是**取最后一个换行之后的内容**（`re.finditer` 循环后只剩最后一个匹配）。

**复现**（本机实测）：

```
40 段 × 100 字（共 4078 字），窗口 1200 → 实际返回 100 字（只剩最后一段）
无换行的 2000 字文本，窗口 1200        → 返回 1200 字（正常）
2000 字 + 末尾换行，窗口 1200          → 返回 0 字（整块丢失）
```

**影响面**：唯一的调用点是 `orchestrator.py:2022`
（`_prose_win = prose_tail("\n\n".join(pieces), _PROSE_WINDOW_CHARS)`，`_PROSE_WINDOW_CHARS=1200`），
注入 `【前文正文（最近片段）】` 块——该块的用途是**压制"同一事件重演 / 同一出场套路复用"**，
且在 `EVICT_PRIORITY` 里是"可淘汰层最后让路"（20，仅次于 `appeared` 19），足见设计上被视为反重演核心。

- 段落长（网文常见）→ 窗口塌缩到 100–600 字；
- 对话密集（段落十几字）→ 塌缩到十几字，**反重演能力基本失效**；
- `pieces` 末段带换行（LLM 输出常见的收尾换行）→ 返回空串，`if prose_window:` 拦掉 → **整块不注入**。

**现有测试反而把 bug 固化了**：`tests/test_prompt_budget.py:74`
`test_prose_tail_cuts_at_paragraph_boundary` 的断言是 `out.startswith(("第二段","第三段"))`
——它只验证"从完整段落开始"，恰好与"返回最后一段"的实现吻合，所以一直是绿的。
`test_..._idempotent_and_tail_preserved` 同理（返回单段后二次调用必然不变，幂等是平凡的）。

**修法**：语义应为"**在 `text[-window:]` 内向前找到第一个段落边界，取其后全部内容**"
（即 `re.search` 而非最后一个 `re.finditer`；并处理边界在位置 0 与末尾换行两种情况）。
配套把测试改成断言"长度接近窗口且 ≤ 窗口"（当前断言会阻止正确修法落地）。

### 1.4 🟠 D4（P1）· ADR-035 实现与自述口径有 4 处不符

ADR-035（`docs/03` 新增节）与 `core/calllog.py` 模块 docstring 都声明了契约，实测对照如下：

| # | 声明 | 实测 | 后果 |
|---|---|---|---|
| 1 | §F「**未 `enable_calllog` 时 `record()` 为 no-op**」（opt-in） | `providers/openai.py:118` 的 `finally` 里 `if not _cl.is_enabled(): _cl.enable_calllog()` —— **首次真实调用即自动开启**；`disable_calllog()` 会被下一次调用立刻覆盖（全库无生产调用点） | 完整 prompt（含未发表正文与私密设定）**无条件**落盘到进程 CWD 的 `raw-calls/`，且**没有任何开关**（无 CLI flag、无 config 键）。CWD 决定落点 → 换个目录跑就散落一份 |
| 2 | §D「脱敏**双保险**：`redact_message` + 正则 `redact_secrets` 兜底」 | `redact_secrets` 在 `src/` 下**零调用**（只被自己的测试调用）——只有一层 | 与自述不符；单层正则一旦漏模式即泄漏 |
| 3 | §D 明确「payload / 原始文本 / 异常串经脱敏」 | `_snapshot` 里 `"payload": payload` 与 `request.messages[].content` **原样写入**，只有 `raw_text`/`exception` 走了 `redact_message` | payload 里的明文设定全量落盘（与 2 叠加） |
| 4 | §C「记录内容（宁全勿缺）」 | `request.messages` 与 `payload.messages` **是同一份内容存两遍** | 磁盘体积直接翻倍（见 D5 实测） |

**另外两处实现细节**（非口径冲突，但值得收）：
- `ts` 用 `time.gmtime()`（UTC），文件名用 `time.strftime('%Y-%m-%d')`（**本地时区**）→
  北京时间 00:00–08:00 写出的记录，`ts` 显示的日期比文件名早一天，按日期 grep 会错位。
- `record()` 不再 `mkdir`（只在 `enable_calllog` 时建一次）→ 运行中删掉 `raw-calls/`
  即静默停止记录（被 `openai.py:125` 的 `except: pass` 吃掉）。

### 1.7 🟡 D7（P2）· `sys.exc_info()` 的潜在污染（当前不可达，但一行可修）

`openai.py:120` 用 `sys.exc_info()[1]` 取"本次调用是否抛异常"。**实测语义**：

```
在 except 块内调用一个正常返回的函数 → 该函数 finally 里 sys.exc_info()[1] 仍是【外层】异常
正常调用路径                            → None
```

即：只要将来出现"在 `except` 里重试 `provider.complete()`"的写法（F14.1 的"改写重试/切换
Provider"正是这种形态），**成功的调用会被记上一条假 exception**。
**当前全库扫描：不存在这样的调用点**（AST 查 `ExceptHandler` 子树内的 `complete(` 调用 = 0），
所以是潜在缺陷。修法：在 `try` 内显式 `ok=True` / `except ... as e: err=e; raise`，
不用 `sys.exc_info()`。

### 1.9 🟡 D9（P2）· 13 处裸 `print` 绕过 io 抽象，且没有 UTF-8 兜底

`orchestrator.py`（1070/1640/1674/1966/1974）+ `forge/engine.py`（4 处）+ `io_console.py` 等，
共 13 处 `print(..., flush=True)`：

1. **cp1252 崩溃面**（与刚修的 `check.py` 同类）：实测 `PYTHONIOENCODING=cp1252 python -c "print('[ch 1-1] 完成')"`
   → `UnicodeEncodeError`。这些是**生成期**的输出，一旦 stdout 不是 UTF-8（重定向到文件、
   非 UTF-8 控制台），会直接打断生成。
2. **绕过 `FilterableIO`**：`forge console` 走 `CliRunner` 捕获 stdout，这些 `print` 的内容
   会**攒到命令结束后一次性刷出**，"实时进度"在 console 模式下失效；`server` 模式下同理。

修法：统一走 `self.io.output` / `click.echo`，或在 CLI 入口做一次
`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（与 `check.py` 同一手法）。

### 2.2 需要额外补充的环节（按杠杆排序）

**S-1 · 润色层缺"术语写法"硬约束（glossary 无最终守门人）** · `core/polish.py:POLISH_RULES`
"【绝对不能改的】"清单列了情节/对白/人名，**没有"专有名词写法必须与术语表一致"**。
而润色是**最后一个动正文的环节**（延迟拟题在润色之后，但只加标题行）；审校是**只读**的，
发现问题只回 `block`→重写（仅事件级）与 `_append_lessons`，**不阻止**已润色文本落盘。
即：模型完全可能把「明善暗恶」润成「明善隐恶」，而没有任何一层拦。
→ 一句话加进 `POLISH_RULES` 的禁改清单 + 把 glossary 作为**独立小节**（现在靠 system 透传，
在 626 字的润色指令里权重极低）。

**S-2 · `director` 层缺境界/铁律** · `DIRECTOR_PROMPT` 只给细纲 + 人物卡 + 近况，
人物卡里虽有 `power.level`，但**没有境界体系与铁律**。导演要产出"本场如何体现（语气、动作、
取舍）"，在不知道"炼气三层打不过筑基"这类硬规则时会给出越级表演指令，
下游润色不改情节、审校才会报"战力越级"——**报错点在最后，成本已经付了**。
→ 复用批次 2 给细纲层建的【世界观基座】块（同一份数据源），加到 director prompt 头部。

**S-3 · forge 大纲层/人物层不注入 glossary、禁用词、铁律** · 批次 2 只给**细纲**节点补了
世界观基座。但**卷/章大纲**（`_volume_prompt`）决定"这一段要发生什么"，
在不知道铁律与术语的情况下排事件，后续只能靠细纲层兜。
→ 把 `_craft_block` 那套"按需注入"扩成 `_worldview_block(st/bp)`，在 volume/chapter/character
三类节点里统一注入（现只有 style 节点有 craft block）。

**S-4 · 缺"章级审校 → 修订"闭环（UC-07 修订返工）** · 事件级有
`block → _REVISE_HINT → 重写一次`（`orchestrator.py:2158-2171`），**章级没有**：
`review_chapter_file` 只在 `novelist review` 命令里手动跑，产出只读报告。
`F4.2`/`UC-07` 要求"基于审查结果自动或人工修订，形成回流闭环"——人工侧有 `promote`，
自动侧缺一环。是否补属**设计决策**（ADR-002 串行优先 + 成本），建议先拍板再动。

## 3. 终端用户体验

### 3.1 🔴 U1（P0）· 默认档 ≠ 手册档，且没有任何预设

实测默认值（`cli.py` 的 `click.option` 与 `orchestrator._produce_chapter_impl`）：

| 开关 | CLI 默认 | 库默认 | 说明 |
|---|---|---|---|
| `--event-loop` | **False** | False | **ADR-013 事件落定即实时回写**、`A9/NFR-13` 的前提 |
| `--polish` | **False** | False | 降 AI 味 |
| `--event-polish` | False | False | 事件级润色（"源头统一风格"） |
| `--readback` | False | False | 回读前章原文 |
| `--supplement-settings` | False | False | 世界观滚动补充 |
| `--agentic-review` / `--agentic-chronicle` | False | False | ADR-032 取证环 |
| `--seam-review` | **True** | **False** | CLI 与库**默认不一致** ⚠ |
| `--volume-facts` | **True** | **False** | 同上 ⚠ |

而 `docs/命令手册.md:52` 对本命令的描述是：
**"串行写一章：圣经注入→事件循环生成→完整性校验→润色→编纂回写"**。

→ 文档描述的是"全开档"，`novelist chapter --vol 1 --ch 1` 实际跑的是"弱档"：
**不事件循环**（因此不逐事件回写记忆，只落一条章级合成事件）、**不润色**、**不回读**。
用户按手册操作，拿到的产物与系统能力不匹配，且**看不到任何提示**。

修法（任选，建议 A+ C）：
- **A**：加 `--profile`（`quick` / `standard` / `full`），`standard` 至少打开
  `event_loop + polish + seam_review + volume_facts`；启动时把生效的开关档打印出来。
- **B**：把手册改成与默认一致（如果弱档才是推荐档）。
- **C**：统一 CLI 与库的默认值（`seam_review`/`volume_facts` 现在两边不一致）。

### 3.2 🔴 U2（P0）· 失败以"成功"的形态呈现

`cli.py:316-343` 的输出在**记忆层全空、禁令未注入、快照未还原**时依然是：

```
wrote draft: …\drafts\chapters\1-1.md (mode=direct, bible=True, attempts=1)
phase: ok
events committed: 0
```

`events committed: 0` 混在成功信息里，**没有告警语义**，`soft_failures` 行也常常为空
（因为 A/B 档那 13 处压根不写 soft_failures，见 D2）。
→ 建议：`events_committed == 0` 且本章应有事件时**显式 WARN**；
`soft_failures` 非空时换成醒目前缀（现在与普通行同格式）；
关键降级（embedding 降级 / 记忆写入失败）在**章节开头**就打一次提示，而不是只在结尾。

### 3.3 🔴 U3（P0）· console REPL 里任何命令出错会**炸掉整个会话**

`forge/console.py:188`：

```python
r = CliRunner().invoke(cli_group, full, catch_exceptions=False)
...
if r.exception:                     # ← 死代码
    self.io.output(f"[error] …")
```

**实测**：`catch_exceptions=False` 时 click 会**直接抛出**，`r.exception` 永远是 `None`：

```
$ invoke(cli, ['forge','show','不存在的目录'], catch_exceptions=False)
→ FileNotFoundError 直接抛出
```

`dispatch()` 与 `run()` **都没有 try/except** → 在 `/chapter`（无蓝图）、`/show`（坏路径）、
`/open`（权限）等任一失败时，**REPL 直接终止并抛栈**，用户丢失会话状态。
→ 修法：`catch_exceptions=True`（让 `r.exception` 生效）+ 在 `run()` 循环里兜一层
`except Exception as e: io.output(f"[error] {e}")`，让错误变成一行提示、REPL 继续。

### 3.4 🟠 U4 · 输出语言中英混杂，且是**同一命令内**混杂

`novelist init` 输出：

```
created project proj-20260915xxxx at …      ← 英文
  stage: 立项                                ← 半英半中
```

`chapter` 的输出标题也是英文（`wrote draft:` / `events committed:` / `completeness:` /
`polish:` / `soft failures:`）而值全是中文；但 `feedback` / `grant` / `settings-pending` 等
命令的输出是纯中文。`forge show` 也是中文。
→ 统一为中文（或统一英文 + `--json`），至少**同一条命令内**保持一致。

### 3.5 🟠 U5 · 帮助文本有实质错误

- `/validate` 在 `HELP_TEXT` 里出现**两次且描述不同**（L597「契约校验（forge validate）」
  vs L625「顶层欠约束一致性检查」）——实际 `dispatch` 只映射到 **顶层 `validate`**，
  L597 的描述是错的；
- 而真正的 `forge validate`（V1–V6 契约校验）在 console 里**根本无法调用**（无对应命令）；
- `/run [工序或--to 工序]` 的写法在 console 里被当成 args 整串透传，`/run --to 正文` 可用，
  但帮助里 `[工序或--to 工序]` 会让用户以为 `--to` 可省；
- 帮助里没有 **provider 相关说明**（`--provider/--api-key/--api-base/--model` 只在启动
  `novelist console` 时能指定，进 REPL 后无法切换）——`F5.3`/`UC-11`（运行时切换 Provider）
  在 console 里不可达。

### 3.6 🟠 U6 · 长任务无进度、无耗时、无"正在做什么"

一次 `chapter` 是 23–43 次 LLM 调用、数分钟到十几分钟，期间只有 5 条 `[ch 1-1] …` 型
`print`（且见 D9：console/server 模式下会攒到最后才刷）。
没有：当前事件序号（`第 2/5 个事件`）、已耗时长、当前步骤名、预估剩余。
→ 建议复用已有的 `log_fn` 通路，输出 `[1-3] 事件 2/5 生成中… (已 03:41)`。

### 3.7 🟡 U7 · `chapter` 有 30 个参数、无分组、无配置化

`cli.py:203-265` 声明了 **30 个 option**（实测），`--help` 会铺满两屏，且**互相关联的组合
没有任何引导**（例如 `--screenplay` 隐含两遍生成、`--agentic-review-rounds` 只在
`--agentic-review` 时生效、`--min-event-words` 只在 `--event-loop` 时生效）。
→ 建议：①`click.option(..., group=...)` 或在 help 里分段；②把这一批开关落进
`config.toml`（`load_config` 已有 `budget`/`security` 段，无 generation 段），
让"我的固定写法"不必每次敲 6 个 flag。

### 3.8 🟡 U8 · calllog 没有开关（UX 视角）

见 D4#1：日志**无条件开启**且只受 CWD 影响。用户既不能"我要看"（其实它一直在写，只是没人告诉他），
也不能"我不要"（`disable_calllog` 无生产入口）。至少应在 `novelist console` / `--help`
里说明"每次调用会写 `./raw-calls/`"，并提供 `--no-calllog` / `NOVELIST_CALLLOG=0`。
