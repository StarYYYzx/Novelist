# 崩溃模式分类表 — 2026-10-09

> 对应用户主命题：「上下文不崩，判定像编译器报错一样客观可测」。
> 依据：全量守卫勘察（规则引擎 13 条规则、审校 9 维度、40+ 检测点）+ 4 份真机崩溃存档
> （前两章问题归因 / v2 评阅 / v5 阶段检查 / prompt 作用审计）。
> 每类按「现有拦截 × 实证案例 × 缺口 × 怎么修」组织；末节回答用户附加问题：
> **如何调用 LLM 与安排上下文处理崩溃，出了问题如何调整**。

## 0. 全景：现有防线的结构性事实

| 等级 | 数量 | 覆盖 |
|---|---|---|
| **block（拦截/重写）** | 仅 5 类 | R-REF 引用悬空、R-TL 时间线倒退、R-LEX 禁用词（DL-005 降级中）、R-STATE 境界倒退、R-THREAD 卷末伏笔 + soft_block 到期 + 厂商审核 + len<20 |
| **warn（提示/注入防线）** | 30+ 处 | 绝大多数守卫是"防线上下文"——写前注入禁令/清单，写后只报告 |
| **fix（自动修复）** | 集中在表面缺陷 | 截断续写、复述去重、元叙事修复、污染名治愈、首登场补写、润色回滚 |
| **queue（人审）** | 构建期为主 | conflicts / covenant / settings_pending / lines 提名 |
| **只报告不修** | **全部语义类缺陷** | 战力、时间线错位、事实矛盾、伏笔、抽取污染——无一有自动修复路径 |

**核心结构性缺口：检测和修复是断开的。** 规则告警（R-*）没有任何修复动作；审校重写仅 1 次且重写稿不再复审；事件循环内不跑规则引擎（v7 ch4"黑板"静默通过的根因）。

| A2 死者再现 | R-STATE warn | — | 只 warn；回忆/提及与实出场未区分 |

## 1. 怎么用"LLM 调用 + 上下文安排"处理崩溃（用户附加问题的正面回答）

**三层防线模型**（现有系统已有雏形，缺的是中间层）：

| 层 | 手段 | 现状 |
|---|---|---|
| **防（注入）** | 硬事实走钉死层（live_state/cast/细纲），防线走禁令注入（重复禁令/回收清单/白名单），事件记忆走结构化账本 | 硬事实和防线已做；**一般事件记忆仍靠 RAG 概率命中** |
| **检（判定）** | 确定性规则（机器可证）+ LLM 审校（语义）+ 事件循环内即检 | 规则只在盘后跑；审校 recall 低且**重写稿不复审** |
| **修（动作）** | fix 路径：表面缺陷已闭环；语义缺陷无修复路径 | **断裂层：规则告警→无动作；审校 block→重写 1 次不复审** |

**四条具体原则**（回答"如何调用 LLM 与安排上下文"）：

1. **机器可证的绝不交给 LLM 判**：状态/时间线/引用类在事件回写后立即跑规则（确定性、零成本），命中带原因重写——LLM 只判机器证不了的（OOC/逻辑/动机）。
2. **防线上下文分层注入**：硬事实（实然状态）钉死；结构约束（白名单/回收清单/事实账本）钉死；经验教训（lessons）**确定性注入而非 RAG 概率命中**（现状是"死参数残余"，审计已定性）。
3. **小目标调用**：每事件一个明确小目标 + 事件后即检即修，出错面最小（已是现状，保持）。
4. **审校要看全证据**：审校已有实然状态注入 + 证据环取证，保持并推广（抽取器同样要求引用原文 span）。

**出了问题如何调整（纠偏闭环）**——每条崩溃归因后三选一：

- **误报 → 豁免表**（现有模式：绑定流豁免、modern_words_exempt、title_rules.json）
- **漏报 → 加检测或加防线**：优先加"防线上下文"（注入禁令/事实账本），其次加规则，最后才加 LLM 判定
- **抽取/回写错 → 加证据约束**（evidence_span 必填、待人工确认通道）

这个闭环现在是**人工驱动**（每轮真机测试→归因报告→修复）；要持续运转需要把"崩溃→归因→三选一"做成 doctor 类的例行体检，而不是每次靠整轮审计。
