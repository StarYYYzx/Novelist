## P0 流程断裂（跨阶段状态破坏 / 用户数据丢失）

### F1. build finally 无条件重写 worldstate，运行态时间线被整体抹掉 ✅已复核
- `forge/engine.py:435-440` finally 块无条件执行 `synthesize_worldstate(bp)` 并写盘；`forge/nodes.py:1678-1731` 该函数恒置 `time.now=0`、characters 回初始态（`location=""`、`injuries=[]`、`dead=False`）、pending 按蓝图 after_days 重算。
- 影响：正文期推进的时间线、人物死亡/受伤/位置、运行态 pending（pd:N）在 build 续跑/重跑后**静默清零**；roll 的 `_roll_context` 随后读到假状态。与"worldstate.time 不推进"旧债同根但更重——不是不推进，是被重置。
- 修法建议：build 只有在 worldstate 文件不存在时才写初始合成（首次初始化语义），存在则跳过。

### F2. tool 模式下 `final` 不是正文，润色后却覆盖整章草稿 ✅已复核
- `core/orchestrator.py:1931-1963`：`--loop`（tool 模式）正文由 write_draft 工具落盘，`final` 是 AgentRunner 的 LLM 结束语（摘要句）；开启 `--polish` 时把这句话润色后 `ws.write_text(draft, final + "\n")` **覆盖整章**。`:1892-1893` 的 completeness 也在对错误文本打分。无任何"final 是否等于草稿内容"的校验。
- 修法建议：tool 模式下 polish/落盘一律以 draft 文件内容为输入源，`final` 只作元信息。

### F3. 跨卷接缝全面断裂：新卷第 1 章无回读、无最近章记忆 ✅已复核
- `orchestrator.py:692-693` `_prior_chapter_text`：`prev_ch = ch-1; if prev_ch < 1: return ""`，且检索固定 `vol == vol` —— 写第 2 卷第 1 章时找的是 (2,0)，必然为空。`orchestrator.py:484-486` `_recent_chapter_memory` 同样卷界截断。
- 影响：跨卷连续性只剩默认关闭的前卷事实清单；卷首"断片"是结构性根因。
- 修法建议：`prev_ch < 1` 时回退到前一卷末章（vol-1 的最大 ch）。

### F4. 事件回写无回滚：半章残留记忆无清理路径
- `memory.py:754-756` `rollback_chapter`（drop_by_source）**全仓库零调用**。事件循环"逐事件实时回写"（ADR-013），第 3 个事件失败 → 前 2 个已写入 plot_events/经历/worldstate/timeline 的残留无自动清理；重跑新旧并存。
- 与 I1-I4（重跑幂等簇）同根：**写章前应先 `drop_by_source(vol, ch)`**。

### F5. `meta.endgame` 是死数据流：用户拍板的结局走向无任何消费者
- `forge/slots.py:92` 定义、`forge/ask.py:297-301` 写入 `bp.data["meta"]["endgame"]`，但全库无读取方；卷规划 prompt（nodes.py:184-194 fixed 块）不含它。注释声称"翻译到 volumes 末卷 summary"从未实现。

### F6. `plant_vol` 被白名单剥离，V6 伏笔密度检查恒空转
- `forge/nodes.py:595` prompt 要求补 `plant_vol/plant_desc`；`nodes.py:1571-1574` sync_bible 白名单无 `plant_vol`（直接丢弃）；`validate.py:442-444` V6 读的是 `planted.vol`——forge 全链路从不写 `planted`。埋设卷信息逐级丢失，伏笔堆积检查半瘫。

### G2. 审查/蓝图连读调用不计入调用预算，文档声称相反
- `engine.py:141-142` docstring 称"会计入调用预算"；实际 `coherence.py:88-90` 直接 `provider.complete` 不触碰 `calls_used`，且每章触发一次全卷重审 → 每卷 O(K²) 次调用，成本不可见、transcript 无痕。

### G3. 接缝复述审查默认关且 CLI 无法打开
- `orchestrator.py:1293` `seam_review: bool = False`；`cli.py:228-236` chapter 命令不透传该参数。确定性去重阈值 0.62（polish.py:138）与实测复述相似度 ~0.29-0.6 之间的"换措辞重演"，唯一防线默认不设防。

### G4. 连读审查 findings 不进细纲，只进正文——介入点与可修正点错位
- findings 的 advice 定义为"给后续章的禁令/替代建议"，但下一章 `_chapter_prompt`（nodes.py:329-425）从不调 `load_coherence_bans`；唯一消费点在正文侧（orchestrator.py:1464-1467）。细纲层发现的母题重复照样固化进账本。

### G5. 润色截断闸门太松
- `polish.py:452-456`：只拦"结尾非句末标点"或"篇幅 <35%"。输出在 60% 处被截且末字恰为句号 → 后 40% 被无声丢掉并覆盖草稿。`finish_reason == "length"` 未检查。

### G6. `revise_book_section` 整段替换绕过 provenance 保护
- `nodes.py:1448-1452` 不查 `is_protected`；正常落库路径 `_apply_items`（nodes.py:876-880）逐字段保护 `src=user`。用户钉死字段可被一次"按建议修订"覆盖，违背 docs/10 §7.6 契约。

### G7. V4 冒烟用 FakeProvider 覆盖真实草稿
- `validate.py:341-345` 跑 `produce_chapter(1,1)`，落盘 `drafts/chapters/1-1.md`——对已有真实草稿的项目跑 `forge report --smoke` 会静默覆盖。
