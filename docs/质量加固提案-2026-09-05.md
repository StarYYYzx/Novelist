## 二、方案明细

### 方案 1：反 AI 味量化引擎（治 C2 / 问题2 / C3，ROI 最高）

**出处**：awesome-novel-agent `skills/anti-ai.md`（六指标三档 + Gate A-F + 误杀豁免 + 收敛规则），源码已核实。

**现状**：`core/polish.py` 只有 3-gram 近重复删句/删段 + StyleMetrics；润色调用是全系统唯一无 system prompt 的 LLM 调用（已知六道防线之一）；口头禅复用（"眼神清澈无辜"ch3×2）无任何机制感知。

**改法**：
1. 新建 `src/novelist/core/prose_metrics.py`：
   - `measure_prose(text, *, exempt) -> ProseReport`，六指标：禁用词密度/千字、排比段数、心理词占比、对话标签密度、平均段句数、**重复描写密度**（高频 n-gram 短语/千字）；轻/中/重三档，总档位取最高。
   - 词表初版抄 awesome `knowledge/anti-ai.md`，跑对照后校准。
2. polish 链路改造（`polish.py` + orchestrator 润色调用处）：
   - **补 system prompt**：注入 style.tone/narration/forbidden_words + 编辑人格——顺手修已知缺陷。
   - 报告驱动：只对"中/重"档涉及的 Gate 类别下改写指令；附 Gate B 对照表（"不是A而是B→直接写B"、"与此同时→直接换场景开头"、"让/令/使→删掉，主语直接行动"——最后这条同时治 C3 转场）。
   - **收敛规则**：同段两轮无改动跳过、全文≤3 轮（现为单次调用）。
3. **误杀豁免表**：`bible/style.json` 增 `catchphrases`（角色口头禅登记，如"运气好而已"），命中指标计 SKIP——防止把角色印记机械删除。
4. few-shot（可选开关）：polish prompt 附 1-2 段 DeepSeek 版（proj-20260903194907）风格样例。

**预期解决**：C2 口头禅、问题2 语气、AI味分波动；C3 部分。
**验收**：`tests/test_prose_metrics.py`（六指标断言/豁免 SKIP/档位判定）；全量回归不破。
**风险**：中文词表误杀率未知——先 warn 不阻断，跑对照后再升硬闸。
**成本**：纯本地计算 + polish 最多 3 次调用（现 1 次）。

### 方案 2：节奏配额与章级契约（治 C1 / C4 / B4）

**出处**：novel-writer `sub-skills/novel-chapter-write/SKILL.md` L41-49（300/800/1500 配额、爽点 60-20-20）、story-skills `continuity.js`（CHEKHOV_CHAPTER_GAP=3）、awesome writer（"字数≥目标90%"）。

**改法**：
1. genre pack 增 `rhythm_quotas`（缺省默认值）；章级 prompt/`render_gist_md` 注入纪律行："每 300 字须有小推进；每 800 字须有情绪转折；连续压抑 ≤1500 字必须释放"。
2. `completeness` 增：章字数 < `target_words_per_chapter`×0.9 → problem（治 C4，现只有 7000 上限）。
3. `consistency/rules.py` 新增 **R-FORESHADOW**：伏笔台账 planted 超 3 章未 payoff → warn（数据源现成）。
4. 细纲校验（`forge/validate`）：turns 数与章篇幅预估不匹配 → 软告警。

**预期解决**：C1（配额强制节奏变化）、C4、B4 制度化部分。
**验收**：`test_rhythm_quota` / `test_chapter_min_words` / `test_rforeshadow`。

### 方案 3：称谓账本 + 审校留档（治 B1 / P5 / B3 取证）

**出处**：novel-writer 称谓表脚本先例；novel-creator `gate_result.json` 产物包（失败也留档）。

**改法**：
1. `relationship_ledger` 扩展称谓维度 `{speaker, target, address, first_ch, evidence}`；Chronicler/关系翻转通道顺带抽取"X 称呼 Y 为 Z"。
2. 人物层注入增"在场者称谓表"；consistency 新增 **R-ADDRESS**：正文称谓与账本矛盾 → warn。
3. 每章审校报告落盘 `reports/quality/v{vol}-c{ch}.json`：`{checks[], failures[], warnings[], prose_report, attempts[{n, prompt_path, text_path}]}`——**重试/修复调用的 prompt 与产出全部落盘**（B3 那种"不知出自哪次尝试"从此可取证）。

**预期解决**：B1、P5。
**验收**：`test_address_ledger` / `test_quality_report`。

### 方案 4：章纲母题去重（治 A1 根因 / A3 / 问题1，最高优先）

**现状实证**：`nodes.py:250 _chapter_prompt` 纪律区无"禁与前章重复"；"前一章必须衔接"被 35B 执行成逐字复读；构建期 `_actual_events_block` 为空（全部细纲正文前盲生成）。

**改法**：
1. `_chapter_prompt` 纪律区加："key_events 严禁与前一章重复或高度相似；『衔接』指因果承接，不是重复叙述"。
2. **确定性闸**：新 gist 与 prev_gist（及近 2 章）key_events 做相似度判定（整条包含 / 字符 Jaccard>0.5）→ invalid → 重生成（≤2 次），重生成 prompt 附"以下事件已使用，禁止复用：…"。
3. A3 侧：hook 纪律语改为**只在最后一个事件**全量注入，前置事件降级为"结局须收束于钩子方向"（防前置事件抢跑写钩子）。
4. 问题1 侧：母题去重天然抑制"代码重构X"标题模板复读；另在章纲 prompt 加"标题禁用前两章已用句式"。

**预期解决**：A1 根因、A2 大头、A3、问题1 的复读放大环节。
**验收**：`test_gist_dedup_gate`（fake provider 复读场景 → 触发重生成）。
**成本**：偶发重生成 ≤2 次/章。

### 方案 5：章间近重复防线（治 A2 残余）

**改法**：
1. orchestrator 章末拼接后：与**上一章正文**跑 `find_near_dup_paragraphs`（复用现有 3-gram），命中进审校清单修复。
2. prose_window 首事件扩为"上章结尾 600 字"（接缝跨章化；现为纯事件摘要回退，弱信号）。

**验收**：`test_cross_chapter_dedup`。

### 方案 6：首登场硬约束 + 广播修复（治 问题3 / B2）

**现状实证**：注入指令存在（orchestrator.py:1351）但为一行软提示；stage 纯按提及数晋升（entity.py:161-171，≥6 次即 established）焊死窗口；`broadcast.py:234` 精确匹配被 name 污染误杀。

**改法**：
1. 首次出场实体（first_ch==0 或 ==ch）的展开介绍行移入 **prompt_budget 钉死层**；文案从"建议展开"改为"必须在本事件内自然交代身份与主角关系"。
2. `completeness` 增：本章新出场实体正文无身份线索 → problem 进审校清单。
3. `parse_decision` 池匹配加**别名归一**：name 去括号注记 + aliases 集合 + 包含匹配兜底（带告警）。
4. 广播拒绝时向事件 prompt 注入禁令行："以下人物未经选角，禁止在正文点名：…"。

**验收**：`test_broadcast_alias_match` / `test_first_appearance_gate`。

### 方案 7：seed 卡 schema 防污染（治 B2 上游 / B1 卡冲突 / 问题1 源头）

**现状实证**：`char:love_interest` 的 name 是 40 字人设长句；林婉清卡与苏晚晴卡同采"青梅竹马"模板。

**改法**：
1. blueprint schema：`character.name` maxLength（12）+ background 必填；nodes.py 人物节点产出后归一（超长描述挪入 background，name 截取）。
2. 构建审查增**卡间冲突检查**：多卡 background/core_traits 命中同一关系模板键（"青梅竹马"等）→ review 警告。

**验收**：`test_name_pollution_coercion`。

### 方案 8：时间底线（治 B5）

**改法**：
1. `nodes.py:306` prompt 改："连续推进填 0；每卷至少 2 章须填明确间隔（1-7 天）"。
2. `forge/validate`：卷内 after_days 全零 → warn；worldstate 回写处：卷末 time.now 未推进 → warn。

**验收**：`test_after_days_floor`。

### 方案 9：章内时序启发式（治 B3，可选，低优先）

**改法**：审校清单增启发式对检（结果词"踉跄/倒地"先于动作词"挥拳/切磋"出现 → warn 供人工）。误报高，仅 warn；P5 留档后主要靠人工取证。

## 三、实施顺序建议

| 批次 | 方案 | 理由 |
|---|---|---|
| 第一批（治根） | 4 → 6 → 7 | A1/A2 是结构性最重；6/7 共享 name 污染根因，一并修 |
| 第二批（治文风） | 1 → 2 | 反AI味引擎独立成模块，节奏配额依赖其指标落地 |
| 第三批（一致性与可观测） | 3 → 8 →（9 可选） | 账本类改动面大，放最后 |

**总验收**：全量回归不破（基线 664 passed / 3 skipped）+ 各方案新测试就位 + 云算力恢复后重跑五章对照，对照指标：dup 段/句、口头禅密度（prose_metrics 重复描写档位）、称谓一致、首登场有身份句比例、章字数达目标 90% 比例、卷内时间推进量。

**新增 LLM 调用成本**：仅 gist 去重重生成（偶发 ≤2 次/章）与 polish 多轮（≤3 次/章，现 1 次），其余全为确定性代码。
